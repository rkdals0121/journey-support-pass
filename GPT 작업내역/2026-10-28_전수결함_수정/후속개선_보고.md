# 오후 5시까지 후속 품질 개선

기준: PR #39 운영 배포 3fbc38b. 후속 브랜치 fix/journey-polish.

## 추가 발견 및 수정

- 미래 예약의 처리 기록이 현장 호출 대기 만료(1시간) 규칙에 들어갈 수 있었다. 계획된 기록은 해당 만료에서 제외하여 다음 날 예약이 오늘 취소되지 않도록 했다.
- 장비 일부가 점검 중이면 전체 중지가 아니더라도 예약 가능 정원을 실제 준비된 대수로 줄인다. 이미 잡힌 좌석 번호가 큰 경우에도 총 예약 수 기준으로 제한한다.
- 예약은 저장됐지만 응답이 끊긴 상황을 재현했다. 기존에는 화면 복귀 후 저장된 예약을 찾지 못했다. 요청 전에 시도 번호를 기록하고, 복귀·온라인 전환 시 기존 건을 조회하여 확인 화면으로 복구한다. 모호한 실패에서는 개인 기기 예약 목록에도 복구 링크를 남긴다.
- 다른 거점 링크·등록 문맥의 초안이 섞이지 않게 나누고, 서버 페이지에 문맥별 컴포넌트 키를 부여했다.
- 단계 제목으로 키보드 초점을 옮기고 Enter가 숨겨진 동의 필드에 막히거나 확인 전에 접수하지 않도록 보완했다.
- 진행 중 예약의 별도 새 접수 링크를 없애고, 완료 후에만 추가 도움 요청을 제공한다.
- 공용 기기에도 실제 직원 이동·지원 상태를 표시한다. 예약 버전이 그대로여도 업무 버전이 증가하면 갱신한다. 오래된 응답은 최신 상태를 덮어쓰지 않는다.
- 직원이 실제 처리 동작을 할 때 근무 기기 쿠키와 담당자 유지 시간을 함께 갱신한다. 배경 조회는 근무를 무기한 연장하지 않는다.
- 세로형 기기 예약 조작 영역을 화면 중앙으로 내려 배치했다.
- 하늘이 테마의 별 개수도 현재 구역의 목표 수와 맞췄다.

## 검증

- 후속 브라우저 흐름 7개 통과: 링크별 초안 분리, 단계 초점·Enter, 도착·동일 건 인계, 기기 직원 이동 표시, 예약 버전 변경 없는 처리 상태 갱신, 여객·기기 동일 건 완료, 90초 안내+30초 유휴 초기화.
- 응답 유실 재현: 수정 전 `serverCommitted=true, recoveredExistingBooking=false`. 수정 후 `serverCommitted=true, recoveredExistingBooking=true, bookingAttempts=1` 확인.
- 추가 서버 검사: 부분 장비 점검 정원, 장시간 근무 중 담당 유지, 미래 예약 보호. 관련 예약·현장 요청 63개 검사 통과.
- TypeScript·소스 린트 오류 0. 최종 전체 CI와 빌드는 배포 커밋에서 확인한다.

후속 테스트는 격리된 로컬 DB를 썼다. 도착 가능 시간 검사의 일관성을 위해 테스트 서버/브라우저 날짜를 2026-10-28 15:45부터 경과시키는 테스트 전용 시계를 사용했다. 유휴 안내는 타이머를 단축하지 않고 90초+30초 실제 경과를 검사했다. 이 시계 설정은 운영 환경에 넣지 않는다.
