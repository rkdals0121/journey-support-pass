# 2차 멘토링 반영 시연·운영 검증

## 적용 범위

사전등록은 유지한다. 새 예약은 사전등록과 별도 확정이며, 패스 화면의 예약 링크로 들어가면 기존 도움 선택을 이어받는다.

- 여객: /visits → 거점·지원·시간 선택 → 확정 → 도착 확인 → 로봇 화면 안내 → 직접 완료 또는 같은 접수로 직원 인계.
- 직원: /staff/visits → 근무 표시 이름·가용 상태 → 도착 예약 수락 → 지연 안내·교대 인계 → 통합 접수에서 현장 처리.
- 거점: /points → 배치도·표지 시안·위치 기반 도움 요청. /points/print의 QR은 거점 안내 주소다. 개인 지원용 QR을 새로 발급하는 기능이 아니다.
- 가족 체험: /stamp 경로형 → 현재 거점·탑승구·선택 탑승 시각 → 같은 터미널의 순방향 거점만 안내.
- 효과: /staff/experience → 이벤트 집계와 별도로 전화/웹·QR 동일 과제의 실측 소요시간·중계·반복 질문·완료를 기록하고 CSV로 내보낸다.

## 시연 기준

운영시간 기본 09–18시, 예약 단위 30분, 거점·서비스별 정원 1은 시연 정책이다. 안내데스크에서 운영시간·정원·준비/중지/충전·재개 예상 시각을 변경한다. 실제 장비 대수나 배터리 원격 측정값이 아니다.

도착 확인은 예약 전후 15분 이내에 한다. 미도착 예약은 시작 30분 후 자동 종료되며, 직원은 시작 15분 이후 미도착을 확인해 종료할 수 있다. 장비 미준비 상태에서는 도착 확인을 막고 예약 변경·현장 지원을 제시한다. 미리 예상한 충전 완료 시각 이후 예약은 가능해도 실제 도착 시 준비 상태는 다시 확인한다.

동일 정원의 마지막 자리는 DB 고유 제약으로 중복 예약을 막는다. 변경 대상 시간이 찼으면 원래 예약을 유지한다. 직원은 한 번에 하나의 도착 예약을 담당하며, 담당 중인 예약을 인계하기 전에는 근무를 종료할 수 없다.

## 현장 시연 순서

1. 여객 예약 후 해당 거점에서 도착 확인 → 로봇 안내 → 완료. 직원 접수가 생성되지 않았는지 확인.
2. 다른 예약에서 도착 확인 → 로봇 응대 → 직원 필요 → 통합 접수 연결. 장소·인원·도움·인상착의 재입력 없이 전달되는지 확인.
3. 두 직원이 같은 예약을 수락 → 한 명만 성공. 교대 사유와 함께 다른 가용 직원에게 인계.
4. 충전/중지 설정 → 여객 시간대 제한 → 직원 지연·대체 안내가 여객 확인 화면에 표시되는지 확인.
5. T2 게이트 경로에 T1 거점이 섞이지 않고, 면세구역 출발 시 보안검색 전으로 돌아가지 않는지 확인.
6. 탑승 시각을 가깝게 설정 → 스탬프 수집 중단과 탑승구 우선 이동 안내.

## 데이터와 효과 해석

예약은 이름·전화·여권 번호를 요구하지 않는다. 종료 24시간 후 인상착의·도움 선택·기기 식별값을 비우며, 예약 상태 이력은 30일 후 지운다. 익명 체험 이벤트는 30일, 실측 비교 자료는 90일 보관한다. 기존 정리 작업과 예약 조회 시 정리가 실행된다.

스탬프의 이름·사진·도장 상세는 브라우저에 남긴다. 집계 API에는 시작·완주·저장 선택 이벤트 종류만 보낸다. 이 값은 이벤트 수이며 검증된 순방문자 수가 아니다. 종이 대체 수량은 담당자가 확인한 실수량만 기록하며 탄소 절감량으로 자동 환산하지 않는다.

배치도·거리·안내 시간·표지 이미지는 시연 자료다. 기관 실내 지도, 출입 권한, 현장 동선, 장비 제조사 API를 제공받은 뒤 실제 운영 기준으로 교체해야 한다. 로봇 화면 응대 완료는 실물 로봇 운행 완료를 뜻하지 않는다.
