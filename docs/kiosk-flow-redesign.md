# 키오스크 확인 이후 흐름 개편 (스케치 2쪽) — 현재와 차이

스케치(2026-11)의 흐름과 지금 코드를 견준 정리다. 이번 PR(첫 화면 개편)은 화면 모양만 바꿨고, 아래 흐름은 **아직 바꾸지 않았다.** 관리자가 순서와 범위를 정한 뒤 별도 PR 로 한다.

## 스케치의 흐름
확인 방법 세 가지(탑승권 스캔 · 여권 스캔 · 예약번호 입력) 가운데 하나로 본인을 확인한 뒤 두 갈래다.

1. **사전예약을 했음**: 예약한 내역을 보여 주고, 추가할 항목이 있으면 더 고를 수 있게 한다. 추가 항목이 없으면 매칭된 로봇이 바로 안내를 시작하고 「즐거운 여행 되세요!」(캐릭터와 함께)를 보여 준다.
2. **사전예약을 안 했음**: 현장등록 화면으로 바로 간다. 어떻게 등록했는지 내역을 보여 주고 추가 항목을 받는다. 추가 항목이 없으면 로봇을 호출하고 로봇이 도착한다.
3. **가용 로봇이 없거나 로봇 운영 시간이 아니면** 직원을 호출할지 묻는다.
4. 위 두 갈래는 **다른 상황**이므로 각각 맞는 문구가 떠야 한다.
5. 입력 방식: 예약번호는 입력 후 버튼을 눌러야 다음으로 간다. **여권은 버튼 없이 카메라에 대면 바로 다음 화면**으로 간다(탑승권 스캔처럼).

## 지금 코드 (확인한 것)
| 단계 | 지금 | 스케치와 차이 |
|---|---|---|
| 확인 | 탑승권 스캔(카메라 QR), 예약번호 입력(숫자판), 여권 스캔 | 여권은 별도 화면에서 **「여권 읽기 (시연)」 버튼**을 눌러야 넘어간다. 실제 여권 인식은 없다(`GuideKiosk.tsx` passport 화면). |
| 사전예약 있음 | `/api/kiosk/resolve` → 「등록한 도움을 확인하세요」(`saved` 화면): 그대로 / 고치기 → **서비스 고르기** | 내역 확인과 고치기는 있다. 그다음 로봇이 바로 안내를 시작하지 않고 **서비스 카드(안내로봇 호출 등)를 고른다.** 「즐거운 여행 되세요!」 끝 화면은 이 흐름에 없다. |
| 사전예약 없음 | 현장등록(`RegisterFlow`, 키오스크 모드) → 서비스 고르기 | 현장등록은 있다. 등록 뒤 로봇 호출은 서비스 카드를 한 번 더 골라야 한다. |
| 로봇 호출 | 서비스 카드 「안내로봇 호출」 → 도움 요청 흐름 | 호출은 있다. 「매칭된 로봇이 바로 안내 시작」은 없다. |
| 로봇 없음·운영 시간 밖 | 운영 시간 규칙(`src/lib/support-operations.ts`)과 장비 배차(`dispatch-resources.ts`)가 있다 | 화면에서 「직원을 부를까요?」로 이어지는 분기는 확인되지 않았다(구현 전에 먼저 확인할 것). |
| 상황별 문구 | 사전예약 화면과 현장등록 화면의 제목·안내가 같은 틀이다 | 두 상황의 문구를 따로 정해야 한다. |

## 정할 것 (관리자 결정)
1. 추가 항목이 없을 때 서비스 카드를 건너뛰고 **바로 로봇 안내로 가도 되는가**(서비스 카드는 「다른 서비스」로 남길지).
2. 「매칭된 로봇」의 기준(가까운 로봇, 가용 로봇 순서 등)과 배정 API 가 이미 있는지.
3. 여권 인식을 **실제로 붙일지**(카메라에서 글자를 읽어 자동으로 넘어가기). 붙이면 개인정보(여권 번호) 처리 방침이 필요하다. 시연에서는 지금처럼 두거나, 버튼 없이 자동으로 넘어가는 시연 동작만 넣을 수 있다.
4. 「즐거운 여행 되세요!」 끝 화면의 문구와 머무는 시간.

## 하는 순서(안)
1. 이 문서의 결정 사항을 정한다.
2. 상황별 문구와 끝 화면(화면만)을 먼저 한다 — 위험이 작다.
3. 「추가 항목 없음 → 바로 로봇 안내」 흐름과 직원 호출 분기.
4. 여권 자동 인식(결정에 따라).
각 단계마다 `scripts/e2e.ts` 의 키오스크 흐름 점검을 함께 고친다.

## 결정과 구현 상태 (2026-11-11)
관리자가 정한 것과 구현한 것.

| 결정 | 내용 | 상태 |
|---|---|---|
| 1. 추가 항목 없음 → 바로 로봇 | 「이대로 안내 받기」(사전예약)와 현장등록을 마치면 서비스 카드를 건너뛰고 **「안내로봇이 오고 있어요」→「약속 장소에 도착했어요」** 화면(나랑이와 함께)으로 간다. 서비스 카드는 「다른 서비스 둘러보기」 단추로 남긴다. | 구현(화면·시연) |
| 2. 로봇 연결 | 시연이라 **실제 로봇을 배정하지 않는다.** 화면이 7초 간격으로 「오고 있어요 → 도착했어요」로 저절로 넘어간다. 다만 로봇을 부를 수 있는지는 기존 운영 규칙(`operatingBlock`: 운영 시간·가용 장비)으로 `GET /api/kiosk/robot-status` 가 알려 준다. | 구현(확인만) |
| 3. 여권 인식 | 시연 수준. 지금의 인식 방식(여권 읽기 시연 단추)을 그대로 둔다. 실제 인식·개인정보 처리는 하지 않는다. | 변경 없음 |
| 4. 끝 화면 | 「즐거운 여행 되세요!」(나랑이 말풍선) 6초 뒤 처음 화면으로. | 구현 |
| (스케치 3) 로봇 없음·운영 시간 밖 | 「지금은 안내로봇이 올 수 없어요. 직원을 불러 드릴까요?」 + 「직원 부르기」·「다른 서비스 둘러보기」. 로봇 운영 시간 기본값은 한국시간 9~18시이고, 직원 화면에서 바꾼다. | 구현 |

고친 내용(「고치기」)을 저장한 뒤에도 같은 로봇 안내 화면으로 간다. 서비스 카드 화면은 「다른 서비스 둘러보기」(로봇 오는 중·도착 화면, 로봇을 못 부를 때)에서 열린다.
