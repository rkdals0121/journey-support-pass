# 서비스별 접수와 기존 탑승권 연결

2026-10-27 팀 피드백 반영.

## 접수 화면

- ‘구역으로 좁히기’와 ‘사진 이용 안내’ 설명을 제거했다. 터미널 선택 기능은 유지한다. 사진 인식은 여전히 기기 안에서 수행하며 서버에 사진을 전송하지 않는다.
- 시설 신고의 시설 이름에는 ‘남자화장실’, ‘엘리베이터’처럼 입력 범위를 예시로 보여주고, 별도 단계에서 근처 게이트 등 신고 위치를 고른다. 신고 위치 선택을 ‘이 위치로 신고’로 표시한다. 신고에 만날 장소나 이동·발화 관련 선호를 묻지 않는다.
- 이동 지원은 동행·휠체어·차량 중 하나를 선택하고 위치를 확인한 뒤 접수 내용을 검토한다. 휠체어·큰 글씨·쉬운 말 등을 재선택하는 공통 질문을 제거했다. 사전등록에 연결된 이동 요청은 이미 저장한 필요 정보를 재질문 없이 전달한다. 로봇의 안내 방식 선택은 로봇 흐름에만 남겼다.
- 교통·주차의 ‘필요한 지원’ 중복 입력을 제거했다. 주차 구역·층처럼 실제 처리에 필요한 항목은 유지한다. 단순 이용 문의는 공식 공항 고객센터 전화와 안내 링크로 연결하며 현장 지원 접수와 구분한다.
- 기타 업무는 고객이 담당 업무를 고르지 않는다. ‘만나지 않음’을 기본으로 두고 담당자가 요청 내용을 분류한다. 대면이 필요하면 해당 선택을 해제하고 실제 위치를 정한다. 온라인 접수 표식은 지도·길 안내·키오스크 설치 위치 목록에 포함하지 않는다.
- 분실물은 웹 신고 양식을 운영하지 않고 주변 직원·안내데스크 직접 인계 및 공식 유실물 안내로 연결한다. 기존 접수 기록을 지우지는 않았다.
- 선택한 위치를 참고도에 표시한다. 현재 참고도는 기존 시연 위치 자료를 그린 도식이며 공식 공항 실내지도나 실제 축척을 의미하지 않는다. 실제 운영에서는 기관 지도 자료로 교체해야 한다.

## 탑승권 판독과 연결

기존 판독기는 QR 전용이었고 일부 화면은 서비스 전용 토큰 모양만 통과시켜 탑승권 코드를 거부했다. 공용 판독기를 QR·PDF417·Aztec·Data Matrix·Code 128 판독으로 확장하고, 브라우저 기본 판독 기능이 없는 경우에도 자체 배포한 ZXing WASM으로 판독한다. 카메라 외에 ‘탑승권 이미지 읽기’ 경로를 제공한다. 이미지 자체는 서버에 보내지 않는다.

모바일·종이 INHA AIR 시연 이미지의 QR와 PDF417은 같은 `BP1:20261028:DX9001:D3M0123456` 내용을 담는다. 서버는 코드에 포함된 날짜·편명과 지원등록을 비교한 후 기존 탑승권 식별자를 서버 전자토큰에 연결한다. 다른 등록의 연결을 덮어쓰거나 날짜·편명을 바꿔 조회하지 못하게 한다. 지원정보를 저장하는 내부 토큰은 유지하되 추가 QR·탑승권·스티커를 고객에게 발급하는 화면은 제거했다. 기존 `/kiosk/register`는 탑승권 기반 현장 등록으로 연결한다.

### 시연 방법

1. 예약 조회에서 DEMO01 / KIM으로 불러와 지원등록을 마친다.
2. 등록 화면의 ‘기존 탑승권 연결 (시연)’에서 이미 제공한 INHA AIR 모바일 또는 종이 PNG를 읽는다.
3. 키오스크·안내데스크·우대출구 화면에서 같은 탑승권을 읽어 연결된 지원정보를 조회한다. 별도 지원 QR은 필요하지 않다.

이미지의 출발일은 2026-10-28이며 해당 날짜·편명으로 등록해야 한다. 같은 탑승권은 한 지원등록에만 연결된다. 반복 시연 시 기존 등록을 삭제한 뒤 새 등록에 연결한다. 판독 성공은 예약 유효성·본인 확인·우대 자격 확인과 구분한다.

### 실제 항공사 경계

단일 구간 IATA BCBP의 필수 영역에서 날짜·편명을 해석하는 경로도 추가했다. 이름과 PNR 원문은 저장하지 않고 서버 HMAC 식별자로 정규화한다. 연도는 BCBP 필수 영역에 없으므로 현재 날짜에 가까운 연도로 해석한다. 여러 구간 탑승권은 아직 지원하지 않는다. 실제 항공사 체크인 시스템의 전자토큰 전달·서명 검증은 연동되지 않았으며, 수동 연결 API는 모의 데이터 모드에서만 동작한다. 실제 배포 모드에서 항공사의 자동 전달을 대신하거나 탑승권 자체를 발행하지 않는다.
