# DX 운영 통합 추가 구현

사전등록은 유지하면서 현장 접수부터 처리 결과까지 연결한다.

## 이번 구현
- 신규 도움 요청, 기존 호출, 기존 이동지원 요청을 공통 업무 목록과 통계에서 조회하고 처리한다. 원본 테이블은 유지하고 중복 복사하지 않는다.
- 안내데스크가 담당 구역을 지정하고 사유를 기록해 인계한다. 진행 상태와 시각은 유지하며, 이전 담당 구역의 처리 권한은 해제한다.
- 신규 요청의 접수·배정·응대·인계·완료 이력은 상태 변경과 같은 트랜잭션으로 저장한다.
- 안내는 배정 후 바로 응대할 수 있고, 이동지원과 로봇 모의 요청은 현장 이동 단계를 유지한다.
- 사전등록 화면에서도 연결된 요청의 진행과 결과를 확인한다.
- 처리 지연, 서비스별·경로별·원본별 현황을 공통 기준으로 집계한다. 자동 만료를 완료 실적으로 집계하지 않는다.

## 검증
- 단위 검사: 29개 파일, 685개 통과.
- 빌드 및 타입 검사 통과.
- 브라우저: 기본 요청 18개, 운영 인계 12개, 키오스크 25개, 통신 복구 12개 통과.

## 남은 범위와 한계
- 실제 로봇·이동장비 제어, 장비 가용 수량과 배차, 기관의 실제 운영 구역·목적지 확정은 남아 있다.
- 백그라운드 알림 전달·수신 확인·재시도까지 포함한 운영 체계는 추가 개발이 필요하다.
- 기존 요청의 과거 처리 이력을 새로 만들어내지 않는다. 신규 요청은 이번 버전부터 이력을 기록하며 기존 신규 요청은 전환 시점의 상태를 기준점으로 남긴다.
- 이전 버전에서 자동 완료된 과거 기록은 실제 완료와 구별할 근거가 없어 재분류하지 않는다.
- 이미 개인정보 연결이 삭제된 과거 요청의 사전등록 연결 여부는 복원하지 않는다.
- 기존 경로와 신규 경로 간 동일 서비스 중복 접수를 확인하지만, 모든 기존 쓰기 경로를 하나의 동시 생성 잠금으로 묶은 것은 아니다.

이는 DX 통합의 운영 처리 단계 구현이며 전체 DX 개발 완료를 의미하지 않는다.
