# 현장 등록 제목·진행 줄 배치 — 미완료 시안

**상태: 초안. 내부 스크롤 0 목표를 달성하지 못했으므로 완료·병합 가능 상태로 표시하지 않습니다.**

기준 main은 48a2e72(#116·#119 포함)입니다. 실제 Chrome에서 기기 3크기 × 글자1·1.5배 × 3진입점 × 15단계를 전·후 각각 270조건 측정했습니다. 임시 스크립트와 큰 JSON은 저장소 밖에 보관합니다.

## 바꾼 부분

- 안내 기기 등록에만 적용하던 16px 루트 예외를 제거해 기존 기기 루트와 --text-page-title을 사용합니다. 소개 화면의 큰 제목 예외는 유지합니다.
- 등록 본문과 진행 줄을 세로 격자로 분리합니다. 항공편 선택 전에도 다음 줄은 비활성 상태로 같은 자리에 둡니다.
- 안내 기기의 단계·요약은 네이티브 details로 접되 이전 단계 수정 기능을 유지합니다. 직원 대신 등록 중에는 기존 업무 메뉴로 옆 목록을 접습니다.
- 본문 끝선은 공용 바의 너비 공식으로 맞춥니다. 긴 내용은 숨기지 않고 본문 안에서 스크롤할 수 있게 둡니다.
- site-bar.css의 원래 데스크톱 높이 선언에 선택적 --flow-bar-height 값을 사용합니다. 기본은 기존 --site-bar-height이며 등록 흐름만 auto입니다. 선택자·휴대전화 규칙·도움 단추의 --site-bar-height 기준 크기·위치는 바꾸지 않았습니다.

## 달성한 것과 달성하지 못한 것

- 문서가 화면보다 긴 조건: 107 → 0. 문서 가로 넘침: 10 → 0.
- 뒤 270조건에서 본문 가로 넘침 0, 바 내부 버튼 겹침·바 밖 단추 0, 진행 줄·본문 끝 도달 불가 0.
- **본문 내부 스크롤 조건은 18 → 114입니다. 전체 스크롤을 없앤 결과가 아니라 문서의 긴 내용을 읽는 칸 안에 둔 결과입니다.**
- 내부 초과 높이는 최대 1899px입니다. 이를 스크롤0으로 보고하지 않습니다. 내용·기능을 삭제하거나 overflow:hidden/clip으로 맞추지 않았습니다.
- 현장 등록은 원래 서류 단계를 건너뜁니다. docs는 세 진입점 모두 해당 없음이며, 서류 절차를 새로 추가하지 않았습니다.

## 비등록 바 보존 및 도움 단추

- 비등록 안내·입구·방문 기록 18조건: 바와 자식 요소의 모든 계산된 CSS 속성 값, 위치·크기, 도움 단추, 문서 높이·가로 넘침 차이0입니다. CSS 속성 나열 순서는 정렬한 뒤 값을 비교했습니다.
- /kiosk는 직원용 설치 화면으로 공용 바·도움 단추·배율 설정 단추가 없습니다. 6조건은 같은 --scale을 콘솔로 적용한 뒤 설치 폼의 계산된 모양을 전·후 비교했습니다. 이 비교도 차이0입니다. 없는 배율 설정 기능을 확인했다고 보고하지 않습니다.
- 등록 안내·입구의 모든 단계 180조건에서 도움 단추의 위치·크기를 같은 크기·배율의 비등록 입구 기기와 비교한 결과 차이0, 다른 바 단추 가림0입니다. 직원 대신 등록은 기존 설계대로 도움 단추가 없습니다.
- 등록 본문·진행 줄의 좌우 끝선도 전 270조건에서 바와 차이0px입니다. 접힌 목록은 6조건에서 키보드로 펼침·이전 단계 이동·선택 유지·목록 끝 도달을 확인했습니다.
- 비등록 24조건의 콘솔 오류0, 등록270조건의 콘솔·페이지 오류0입니다.
- 여객 /register의 390×844·1333×750도 전·후 계산된 모양 차이0을 확인했습니다. #114의 휴대전화 규칙과 지도는 수정하지 않았습니다.
- 설치 화면 자체의 기존 세로 넘침은 그대로입니다: 1920×1080에서 doc1205/1799(배율1/1.5), 1024×768에서 doc1189/1776, 1080×1920에서 doc1920/1920입니다. 이번 등록 흐름 수정 범위에 포함하지 않았습니다. 여객 웹 등록도 390×844에서 doc1022, 1333×750에서 doc750으로 전후 같습니다.

## 남은 선택지 — 구현 전 결정 필요

1. **긴 질문·확인 묶음을 나누기(추천).** 걷기·전동차 등 여러 묶음을 한 번에 표시하는 질문과 긴 확인 목록을 여러 화면으로 나눕니다. 모든 내용을 유지하며 큰 글자를 읽기 쉬우나 단계 수·진행 표시·소리 안내·e2e 순서가 바뀝니다. 이 시안에는 구현하지 않았습니다.
2. **문서 스크롤0 + 본문 내부 스크롤 허용.** 현재 시안처럼 진행 줄을 고정하고 내용을 끝까지 읽습니다. 구조 변경이 작지만 화면 가이드의 모든 스크롤0 목표에 대한 예외 승인이 필요합니다.
3. **설명·확인 내용을 요약과 펼침으로 나누기.** 내용은 유지할 수 있으나 중요한 동의 정보가 처음부터 보이지 않을 수 있고, 펼친 상태의 스크롤은 별도 해결해야 합니다.
