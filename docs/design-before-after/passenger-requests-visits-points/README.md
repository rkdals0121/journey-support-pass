# 여객 웹 `/requests` `/visits` `/points` 화면 정리

기준 화면은 웹 첫 화면(`/`)이다(`docs/ui-guide.md`). 세 화면 모두 위쪽 바 + 노란 소개 박스(`.ph-hero`) + 흰 카드 틀로 맞췄다. `/check` 는 이 묶음에 넣지 않았다(따로 작업).

## 바꾼 것
- `/points`: 소개 박스 + 첫 화면과 같은 카드 격자(`.ph-list` / `.task-action`, 아이콘 칩, 높이 같음). 「시연용 배치」 안내는 소개 박스 위 한 줄로 합쳤다.
- `/visits`: 소개 박스(제목 + 한 줄). 시연 예약 안내는 소개 박스 위 한 줄. 폼·지도 칸은 같은 카드 모양(`border-color-line`, `radius-medium`). 낮은 화면(`max-height: 700px`)에서만 여백·단추 높이를 줄였다(기능은 그대로).
- `/requests`: 소개 박스 + 요청 카드(`.my-service-request`, 첫 화면 카드와 같은 모양). 요청이 없을 때는 카드 하나. 개인정보 안내는 한 줄로 줄였다.
- 이 기기의 예약(`SavedVisits`): 같은 카드 모양.
- CSS: `passenger.css` 안에 세 곳으로 흩어져 있던 `.my-service-*` 규칙 19줄을 한 블록으로 합쳤다. 새 CSS 파일 없음, `!important` 없음, 색 코드 없음.

## 남은 문제
- 휴대전화(390)에서 `/visits` 는 폼이 길어 스크롤된다(허용 범위). 이 묶음에서 키오스크 크기(1920×1080, 1024×768, 1080×1920)는 재지 않았다. 세 화면은 키오스크로 가면 `/kiosk/*` 로 넘어간다.
- 요청이 있는 상태의 `/requests` 카드 모양과 글자 1.5배는 그림으로 확인하지 못했다.
- 개인정보 안내에서 「다른 기기에서는 저장한 접수 링크로 열어 주세요」 문장을 뺐다(글 최소화).
