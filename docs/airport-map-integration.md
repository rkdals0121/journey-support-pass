# 시설 터치 지도 연결

## 연결 화면

- `/navigate`: 기존 목적지 종류 선택창·탑승구 번호 입력을 시설 검색 및 터치 지도로 교체했습니다. 지도는 경로 보기 버튼 위에 표시됩니다. 출발지 선택/목적지 선택을 전환할 수 있습니다.
- `/help?topic=mobility`: 이동 동행·차량 지원의 ‘가고 싶은 곳’ 선택창을 검색 및 터치 지도로 교체했습니다. 선택은 기존 요청의 destinationId에 저장됩니다. 휠체어 수령만 하는 업무에는 목적지를 지정하지 않습니다.
- 메인 화면의 기존 메뉴 링크를 유지합니다. 새 사이트 또는 별도 메인 화면은 추가하지 않았습니다.

## 시설 선택 및 데이터 계약

- `FacilityMapPicker`가 검색·터미널 전환·터치 선택·선택 해제·선택 결과 표시를 공통으로 처리합니다.
- 시설 ID는 `map-poi-<원본 시설 ID>`입니다. 서버와 화면이 동일한 `airport-facilities.json`을 사용하며 브라우저가 전송한 이름·좌표를 신뢰하지 않습니다.
- 요청 서버는 기존 목적지와 새 시설 ID를 모두 지원합니다. 새 시설은 출발 위치와 같은 터미널·같은 보안구역·3층인 경우만 허용합니다. 모르는 ID는 거절합니다.
- 이용객의 확인 화면·접수 후 조회 화면·직원 요청 목록은 동일한 목적지 표시 함수를 사용합니다.
- 시설을 운영 거점이나 만날 곳으로 등록하지 않습니다. 기존 거점·정원·예약 데이터 구조는 유지합니다.

## 길찾기

기존 위치가 탑승구인 경우 터미널·번호가 일치하는 지도 시설에 연결합니다. 그 외의 위치를 임의의 좌표에 놓지 않습니다. 일반 이용자는 지도에서 출발 시설을 직접 선택할 수 있습니다. 고정된 키오스크 위치를 매칭하지 못하면 직원 안내를 요청합니다.

경로는 지도 통로 그래프에서 계산하며 지도에 표시합니다. 다른 터미널·보안구역, 연결되지 않은 통로는 경로를 표시하지 않습니다. 시설이나 출발지를 바꾸면 이전 경로가 지워집니다. 현재 자료는 3층 시연 데이터이며 실제 계단 없는 접근성을 보증하지 않습니다.

## 검증 및 남은 사항

타입 검사·ESLint·Next.js 빌드와 시설 ID/보안구역 검증·요청 저장/재조회 회귀 검사를 실행했습니다. 이 실행 환경의 미리보기 도구는 Next.js가 지원하지 않는 --host 옵션을 추가하므로 브라우저 터치 및 반응형 실기기 QA는 미검증입니다.

이 수정은 기존 지도 브랜치 위에 적용하는 코드 변경이며 GitHub 푸시·실서비스 배포를 수행하지 않았습니다. 공식 지도 엔진·도면의 공개 재배포 허락은 `THIRD_PARTY_NOTICES.md`에 기록한 대로 미확인입니다. 공개 배포 전에 권리 확인 또는 대체가 필요합니다.

만남 사전 예약(`/visits`)과 로봇 자동 이동은 이번 수정 대상이 아닙니다. 예약 화면에 26개 입구 체크포인트를 연결하려면 운영 거점과 체크포인트 관계 및 저장·운영 화면 연동이 별도로 필요합니다.
