# 입구별 지도 PR 검토 및 후속 연결

## 이번 수정

- ESLint에서 `public/airport-map/assets/**`에 있는 외부 배포 번들만 제외합니다. 직접 작성한 map.js, graph.js, React 컴포넌트 검사는 유지합니다.
- 자료 출처와 공개 재배포 허가가 미확인이라는 상태를 `public/airport-map/THIRD_PARTY_NOTICES.md`에 기록했습니다. 이 문서를 추가했다고 권리 확인이 해결된 것은 아닙니다.

## 예약 연결 전 확인할 데이터 계약

현재 `/visits`의 `VisitForm`과 `/api/visits`는 `SERVICE_HUBS`의 6개 `hubId`로 예약을 저장합니다. 운영 시간·정원·로봇 자원·현장 확인도 이 거점 ID에 연결돼 있습니다.

새 지도는 별도의 `meeting-t1-1` 등의 26개 체크포인트 ID를 반환합니다. 이 값을 기존 `hubId`에 그대로 넣으면 지원하지 않는 거점으로 거절됩니다. 반대로 화면에만 입구 지점을 보여주고 기존 데스크 hubId로 예약하면 이용객이 보는 장소와 운영자에게 전달되는 장소가 달라집니다. 그런 임시 연결은 적용하지 않았습니다.

권리 확인 또는 지도 자료 교체 후, 다음을 하나의 변경으로 진행해야 합니다.

1. 운영 거점과 체크포인트의 관계 및 입구별 서비스 가능 여부 결정
2. 서버가 체크포인트 ID를 기준으로 좌표·터미널·층을 검증하도록 구현
3. 예약 및 예약 변경 트랜잭션에서 체크포인트 저장·조회
4. 날짜·시간·운영 정원과 선택 지점의 연결 유지
5. 예약 확인·직원 화면·키오스크에서 동일한 만날 곳 표시
6. 변경·재시도·중복·다른 보안구역·지원하지 않는 지점의 회귀 검사

지도 직접 확인 경로는 `/airport-map/index.html`입니다. 현재 예약 화면과 데이터베이스에는 입구별 체크포인트가 연결되지 않았고 실제 로봇 자동 이동도 구현하지 않았습니다. 공식 재배포 허가를 확인하기 전 이 지도를 운영 화면에 노출하도록 연결하지 않았습니다.
