# 서비스 직접 이용과 접수·처리

| 진입 | 앱에서 제공하는 동작 | 처리 연결 |
|---|---|---|
| 길·시설 안내 | 현재 위치 확인, 탑승구·시설 선택, 계단 없는 경로 계산 | 안내가 어려우면 현장 안내 요청 |
| 이동지원 | 동행·휠체어·차량 구분, 위치·목적지·인원 | 이동지원 업무 접수·배정·장비 확인·진행 |
| 시설 불편 | 청소 또는 시설 이용지원 구분, 시설·불편 내용 | 터미널별 미화 또는 여객터미널 업무, 결과 기록 |
| 교통·주차 | 주차 구역·노선·지원 유형 | 터미널별 교통 업무 접수·처리 |
| 분실물 | 분실·습득 구분, 물품 특징·한국 시간·위치 | 여객터미널 업무 접수·처리 결과 |

상담·전화 연결을 공통 종착점으로 사용하지 않는다. 서비스별 항목은 서버에서 검증해 `service_requests.service_details`에 저장하고, 영수증 상태와 직원 통합 목록에서 동일하게 조회한다. 신고 유형·필수 항목·선택값·길이·미래 시각을 검증한다. 터미널 담당 업무가 달라지는 신고 위치 변경은 새 접수가 필요하다.

모바일 도움 요청은 서비스→위치→추가 내용→검토로 진행한다. PC는 입력과 요약을 나란히 둔다. 처리 상세는 현재 단계·결과를 먼저 보여주며 위치 변경은 보조 동작으로 접는다. `/requests`는 같은 탭에서 성공한 최근 10개 접수 확인값을 보관해 여러 요청을 확인한다. 공개 확인값은 조회 링크를 가진 사람만 사용할 수 있고, 기존 24시간 만료·순차 삭제 정책을 따른다. 공용 키오스크는 개인 요청 목록을 열지 않으며 다음 여객 초기화 흐름을 유지한다.

설치된 로봇 화면은 1080×1920 세로 화면의 한 열 구성을 사용한다. 안내 키오스크는 별도 스캔·번호 입력·서비스 진입을 제공한다. 공개 기기 미리보기는 예시다.

기관 실내 지도, 공식 분실물 원장, 주차·교통 시스템, 실물 로봇·차량의 운영 API를 연동한 변경은 아니다. 경로는 기존 시연 지도에서 계산하고, 접수·담당 배정·결과 공유는 이 앱의 실제 데이터 흐름으로 동작한다. 공식 예약 확정이나 실물 출동으로 표시하지 않는다.

배포 전 새 스키마를 먼저 적용한다. 기존 인증된 `/api/admin/setup`에 빈 객체를 보내면 스키마만 적용하고 직원 코드·운항 데이터는 초기화하지 않는다. 검증 배포에서 스키마를 적용한 다음 main 배포를 진행한다.
