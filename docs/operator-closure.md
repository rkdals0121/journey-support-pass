# 안내데스크의 현장 확인 후 종료

신규 통합 요청과 이전 호출·이동지원 요청을 실제 완료와 구분해 운영자가 종료할 수 있다. 과거 중복·지원 중단 기록을 완료 실적으로 처리하지 않게 한다.

## 운영 규칙
- 안내데스크만 사용할 수 있다. 현재 요청 버전, 현장 확인 체크, 120자 이내 사유가 모두 필요하다.
- 종료 상태는 취소이며 완료 건수에 포함하지 않는다. 신규 요청은 여객에게 사유를 표시하고 기존 업무 이력에 처리 구역·사유를 기록한다.
- 이전 호출·이동지원은 종료와 동시에 원본에 처리 구역·사유·종료 버전을 저장한다. 이전 여객 화면의 취소 상태에도 반영한다.
- 이전 기록의 과거 전체 업무 이력을 소급 생성하지 않는다. 이번 버전 이후 실제 운영자가 종료한 사건만 이력으로 표시한다.
- 대기 중 위치 변경을 정리하고 장비의 활성 배차와 등록·서비스 공통 잠금을 해제한다.
- 담당자가 체크한 뒤 요청 버전이 바뀌면 확인 체크를 해제한다. 오래된 화면의 종료는 서버 버전 검사에서도 거절한다.

## 이전 경로의 버전
- 이전 두 원본에도 변경 횟수 기반 버전을 둔다. 시간과 단계만으로 버전을 추정하지 않는다.
- 익명 호출에 같은 시각을 유지하면서 패스를 붙인 경우도 새 버전이다. 기존 기기·API가 갱신한 상태에도 버전이 증가한다.
- 통합 화면의 기존 요청 수락·이동·완료·운영자 종료는 원본 갱신 조건에 버전을 포함한다.
- 기존 요청의 원래 API 처리 규칙은 유지한다. 새 버전 반영 직후 오래 열린 통합 화면은 최신 상태를 다시 읽어야 할 수 있으며 409 응답 시 즉시 갱신한다.

## 보관과 검증
- 이전 요청의 종료 사유도 생성 후 최대 24시간 안에 비우고 등록 정보 삭제 시 즉시 비운다. 익명 처리 구역·종료 시각은 보존한다.
- 사유를 비우면서 현재 원본 버전이 바뀌어도 실제 종료 사건의 버전과 시각은 바꾸지 않는다.
- 종료된 이동지원의 오래된 메타데이터도 기존 90일 보관 정리에 포함한다.
- 권한·확인·사유·경합·패스 연결·버전·완료/시간 초과 구분·정보 삭제·이력 저장 실패 시 롤백을 검사한다.

실제 장비를 자동 정지시키는 기능은 아니다. 현장 확인 체크는 담당자가 실제 지원 상태를 확인한 뒤 사용하도록 만든 운영 절차다. 장비 대장은 계속 시범 운영 상태다.
