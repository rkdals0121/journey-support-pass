# 출발지 현재 위치·가까운 목적지 지도 변경 검토

## 최신 코드 기준 및 범위

작업 전에 기존 변경을 보존하고 원격 지도 브랜치를 가져온 뒤 `git pull --no-rebase --no-edit origin main`으로 최신 main(e1bc0fa, PR #65)을 병합했습니다. 새 작업 브랜치는 feature/airport-map-current-nearby입니다. 원격 푸시는 하지 않았습니다.

## 변경 이유와 결과

- 출발지 옆 ‘현재 위치’는 기기에 등록된 위치로 되돌립니다. 키오스크도 출발지를 직접 바꿀 수 있습니다.
- 현재 위치가 지도 시설 ID와 연결되지 않았다면 임의 좌표를 만들지 않고 버튼을 비활성화합니다. 일반 PC·모바일의 GPS나 실제 로봇 실시간 좌표를 새로 수집하는 기능은 아닙니다.
- 출발지 표시는 목적지를 선택할 때도 지도에 남습니다.
- 화장실 등 시설을 고르면 같은 터미널·보안구역에서 그래프로 연결 가능한 후보를 통로 거리로 정렬합니다. 최대 3개 후보를 제시하고 선택하면 경로·거리를 즉시 표시합니다.
- 출발지 변경·현재 위치 복원·출발지와 목적지 바꾸기에도 경로를 다시 계산합니다.
- 선택한 시설 분류는 그대로 유지합니다. 다른 시설 아이콘은 숨기고, 선택적으로 주요 위치 글자만 남깁니다.
- 키오스크는 가로·세로 모두 화면 전체 폭을 사용하고, 경로 요약을 지도 아래에 두어 가로 지도를 넓힙니다.
- 서버 예약·요청 데이터 구조는 변경하지 않습니다. 이동 지원의 기존 저장 연동은 유지합니다.

## 디자인 규칙 적용과 지역 구조 예외

기존 지도 지역 CSS 모듈 두 개에서 색·글자·간격·모서리를 기존 토큰으로 바꾸고, 새 반응형 조건은 760 / 761–1100 / 1101 이상 및 700 높이 기준으로 맞췄습니다. 키오스크 버튼은 4rem 이상입니다. layout.tsx에 CSS를 덧붙이지 않습니다.

지도 중심의 PC 작업면은 기존 폼 최대폭(--col=32.5rem)보다 넓어야 출발·목적지, 지도와 요약을 함께 볼 수 있어 데스크톱 최대폭 70rem을 사용하는 지역 구조 예외를 유지했습니다. 모바일은 --col을 따릅니다. 키오스크는 지도 가로폭을 대폭 늘려 달라는 추가 요구에 따라 최대폭 제한을 풀고 한 열로 배치하며 요약은 지도 아래로 옮깁니다. 이 예외는 ‘지도 활용을 극대화’하려는 요구를 반영하며 토큰을 다시 정의하지 않습니다.

## 검증

- TypeScript 및 ESLint 오류 없음(기존 스탬프 이미지 경고 2개).
- 전체 Vitest 988개 통과, 5개 건너뜀.
- Next.js 프로덕션 빌드 성공.
- 실제 컴포넌트로 구성한 별도 브라우저 검증 화면에서 130번 탑승구 출발 → 화장실 후보 약 46/101/187m 정렬 → 선택 → 약 46m 경로 자동 표시 확인.
- 키오스크 출발지를 132번으로 수동 변경한 뒤 현재 위치 버튼으로 130번 복원하고 목적지·경로가 재계산되는 것 확인.
- 390×844, 320×640, 768×1024, 1280×633, 1366×657, 1920×937, 가로 키오스크 1280×800, 세로 키오스크 1080×1920을 각각 글자 1 / 1.5배로 확인. 검증 컴포넌트에 가로 넘침·본문 버튼 최소 크기 미달 없음.
- scripts/layout-check.ts 및 scripts/e2e.ts 전체 서비스 검사는 실행하지 않았습니다. 위 배치 검사는 해당 지도 컴포넌트의 별도 브라우저 검증이며 전체 서비스 검사를 대신하지 않습니다. 배포 전 실제 서비스·기기 및 Vercel 미리보기에서 추가 검증이 필요합니다.

기존 엔진·도면·시설 데이터의 공개 재배포 허가 미확인 상태는 THIRD_PARTY_NOTICES.md를 유지합니다. 실제 로봇 제어 및 예약 운영 거점 연동은 별도입니다.
