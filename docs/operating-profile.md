# 시연 운영 기준 — 2026-10-26

사용자 결정: 인천공항운영서비스의 기존 업무 전체를 범위에 포함하고, 위치·목적지·시간·장비 가용 조건은 팀이 시연용으로 설정한다.

## 근거와 적용

- 공식 사업현황: https://airportos.co.kr/?act=info.page&pcode=business
- 공식 4개 분야·12개 사업을 `src/lib/operating-profile.ts`에서 관리한다. 터미널 운영 3개, 교통 운영 3개, 환경미화 3개, 시설 운영 3개다.
- 2차 멘토링 필기(라연·병현)의 여객 서비스 중심, 접수→담당자 연결, 사전등록 유지 방향을 따른다.
- 전사 사업 안내와 현재 앱의 처리 능력은 구분한다. 앱의 직접 처리 흐름은 직원 안내·로봇 모의 호출·이동지원 상담이며, 각 전문 부서 업무는 직원이 연결한다.
- 귀빈실 이용·항공기 탑승교 조작·자료관리 등을 일반 여객의 자동 예약·실행으로 표현하지 않는다. 공식 위탁 사업 범위를 공항 전체 운영 권한으로 확대하지 않는다.

## 화면

- `/services`: 한국어·영어 12개 사업 안내. 여객 상담·담당 부서 연결·내부 전문 업무를 구분한다.
- 사업 상담 버튼 → `/help?business={canonical-id}`: 검증된 사업명의 상담 문구를 추가 말씀에 미리 넣는다. 사용자가 검토·수정 후 기존 동의·접수 절차를 거치며 직원 목록·이력에 기존 요청으로 반영한다. 별도의 전문 부서 시스템으로 자동 송신하지 않는다.
- `/staff/operations`: 직원 인증 후 시간·담당 범위·실제 시연 대장 상태별 수량·픽업별 목적지 후보를 확인한다.
- 첫 화면·도움 요청·통합 요청·장비 대장에 진입 링크를 추가한다. 사전등록은 그대로 유지한다.

## 시연 설정

| 항목 | 설정 |
| --- | --- |
| 접수·처리 시간 | 한국시간 24시간 시연. 실제 각 부서 영업시간을 뜻하지 않음 |
| 여객 위치 | 기존 T1·탑승동·T2 지점 + T1·T2 1층 도착장 시연 만남 지점 |
| 목적지 후보 | 등록된 다른 지점 중 터미널·보안 구역이 같은 곳 |
| 목적지 확정 | 현재는 직원 상담으로 확인. 별도 목적지 필드·자동 이동 명령 없음 |
| 구역 간 이동 | 일반·보안 구역 경계를 넘거나 터미널을 바꾸는 자동 경로 후보는 제공하지 않음 |
| 직원 | 안내데스크 접수·배정·인계, 담당 구역 현장 처리, 전문 부서 연결 |
| 가용 | 활성 구역에서 ready 상태이며 활성 요청에 배차되지 않은 장비 |
| 배차 | 기존 서버의 종류·권한·진행 단계·위치 변경·중복 배차 검사를 계속 적용 |
| 배터리·고장·적합성 | 센서값을 꾸며 넣지 않고 담당자가 확인 후 가용·점검·중지로 설정 |
| 자원 수량 | 현재 DB 대장의 실제 시연 기록. 공식 장비 보유 수량을 복사해 실장비처럼 등록하지 않음 |

## 후속 범위

기관의 실제 업무 연락망·권한·부서 시스템, 확정 목적지의 구조화 저장, 실장비의 위치·충전·상태 수집 및 명령은 별도 연계 범위다. 이번 적용은 운영 기준과 사업 안내·상담 진입을 구체화한 것이다.
