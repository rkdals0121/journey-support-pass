# 담당 업무 분류와 처리 결과 연결

## 목적

여객의 요청 유형과 직원이 확인한 담당 업무를 구분하고, 상담 이후 실제 처리 내용을 같은 접수에 남긴다. 외부 부서 시스템이나 장비를 연결한 것으로 표현하지 않는다.

- 진행 중 요청의 담당 업무는 안내데스크 또는 해당 담당 구역이 사유와 함께 변경한다. 요청 유형·담당 구역·진행 상태는 유지하고 기존 이력에 변경 전후 업무를 기록한다.
- 직원 목록은 12개 담당 업무별로 필터링할 수 있다. 필터와 집계 건수·페이지 조회에 같은 조건을 적용한다.
- 시설·교통·분실물·기타 상담은 응대 이후 처리 결과를 필수로 기록한다. 기존 직접 지원 요청은 기존 완료 동작을 유지하며 결과를 선택적으로 기록할 수 있다.
- 결과는 상담 완료, 담당 창구 안내, 담당 부서 인계 확인, 현장 조치 완료 확인으로 구분한다. 창구 안내는 부서의 접수 완료가 아니다. 인계 확인은 문제의 해결 완료가 아니다.
- 인계와 현장 조치는 직원이 직접 확인했다고 체크해야 기록한다. 이는 외부 API 수신 확인이나 기관 인증을 뜻하지 않는다.
- 여객에게 전달할 결과 메시지(240자 이내), 담당 업무와 결과 유형을 완료 상태·이력과 원자적으로 저장한다. 다른 직원이 먼저 처리한 경우 최신 버전 확인이 필요하다.
- 여객의 요청 상세·포털 내 요청·유효한 사전등록 조회에 같은 결과를 표시한다. 입력한 메시지를 자동 번역하지 않는다.
- 보관 기간 종료 및 등록 개인정보 즉시 삭제 시 결과 메시지·결과 업무·결과 유형을 제거하고 기존 개인정보 정리 경로를 유지한다.

## DB·배포

`service_requests`에 `resolution_kind`, `resolution_business_id`, `resolution_message`를 추가하고 공통 업무 뷰 끝에 해당 열을 추가한다. 이전 버전과 호환되는 추가 변경이다. 배포 전 새 검증 배포에서 스키마만 적용한다. 코드·항공편·장비 초기화는 필요 없다.

## 검증

`tests/request-resolution.test.ts`는 결과별 저장, 명시적 확인, 필수 입력, 소유 권한, 동시 완료 충돌, 업무 변경 이력·필터, 이력 실패 시 원자성, 보관 종료와 즉시 삭제, 사전등록 결과 조회를 검사한다.

`scripts/business-resolution-e2e.ts`는 로컬 전용 실제 브라우저 검사다. 직원 업무 수정·필터·배정·응대·인계 확인·완료부터 여객 상세와 포털의 결과 확인까지 검사한다. 운영 요청을 생성하지 않는다.
