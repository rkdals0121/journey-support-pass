# Journey Support Pass 웹앱 개발 명세

- 기준 문서: 제안서 수정본 (팀의 "제안서 수정" 판)
- 처음 쓴 날: 2026-10-05
- 고쳐 쓴 날: 2026-10-09 (제안서 수정본에 맞춰 구조를 바꾼 뒤 전체를 다시 썼다)
- 상태: 시제품. 여객 정보는 모의 데이터, 운항 정보는 실제, 길과 시설 위치는 시연용 모의 자료다. 구현·배포 현황은 14장

## 1. 목적과 범위

여객이 필요한 안내 방식을 한 번 골라 두면 QR 패스가 나온다. 공항의 안내 키오스크에 그 QR을 대면 화면과 길 안내가 그 여객에게 맞게 바뀐다.

예전 구조와 다른 점은 하나다. 패스가 직원에게 정보를 넘기는 것이 아니라, **공항의 안내 기기가 여객에게 맞춰진다.** 직원은 여객이 「직원 부르기」를 눌렀을 때만 온다.

### 이번에 만든 것

| 화면 | 쓰는 사람 | 하는 일 |
|---|---|---|
| 등록 (휴대전화) | 여객 | 일곱 가지를 차례로 고르고 패스를 받는다 |
| 패스 (휴대전화) | 여객 | QR과 번호를 보여준다. 내 항공편을 보고, 등록을 직접 지운다 |
| 등록 키오스크 | 여객 | 공항에서 등록하고 QR 스티커를 뽑는다 |
| 안내 키오스크 | 여객 | QR을 대면 고른 방식대로 항공편, 탑승구 가는 길, 가까운 시설을 보여준다 |
| 직원 호출 화면 | 현장 직원 | 여객이 누른 「직원 부르기」를 받고 마친다 |
| 안내데스크 화면 | 안내데스크 직원 | 여객 대신 등록, 패스 찾기(스티커 다시 뽑기·지우기), 오늘 현황 |
| 키오스크 설치 | 직원 | 기기 한 대를 키오스크로 만든다 |
| 운항 정보 수집, 자동 삭제 | 서버 | 정해진 간격으로 스스로 돈다 |

### 만들지 않은 것

- 직원이 여객 목록을 보는 화면, 여객 카드, 응대 기록. 직원은 먼저 다가가지 않으므로 없앴다.
- 이름, 연락처, 진단명, 교통약자 구분을 받는 칸. 받지 않는다.
- 여객이 등록 내용을 고치는 기능. 고치려면 지우고 다시 등록한다.
- 이름으로 패스를 찾는 기능. 이름을 받지 않으므로 만들 수 없다.
- 안내 로봇 전용 화면. 안내 키오스크 화면 하나만 있다. 로봇에 이 화면을 띄울 수 있는지는 기업탐방에서 묻는다(13장).
- 실제 실내 지도. 길과 시설 위치는 모의 자료다(8장).
- 한국어·영어 외의 언어.
- 직원 개인 계정. 접속 코드를 쓴다.
- 관리 화면. 측정값은 안내데스크의 오늘 현황과 운영자용 명령으로 본다.

### 데이터 수준

시범은 모의 데이터로 한다.

- 환경 설정 `DATA_MODE=mock` 이 기본이다. 이때 모든 화면 위에 "시범 운영 · 모의 데이터 · TRIAL" 띠가 뜨고, 등록에는 모의 표시(`is_mock`)가 붙는다.
- `DATA_MODE=live` 는 기관의 개인정보 검토가 끝난 뒤에만 쓴다.
- 길과 시설 위치는 `DATA_MODE` 와 상관없이 모의 자료다. 길 안내 화면 아래에 "길과 시설 위치는 시연용 모의 자료입니다"를 적는다.

## 2. 제안서와의 대응

제안서의 내용을 웹앱의 어디에 구현했는지 적는다. 왼쪽 칸은 제안서 문장을 그대로 옮긴 것이 아니라 요지다.

| 제안서의 내용 (요지) | 웹앱에서 구현한 곳 |
|---|---|
| 여객이 사전에 휴대전화로 등록한다 | `/register`. 마치면 `/p/{token}` 으로 넘어가고 그 화면이 패스다 |
| 사전 등록을 못 한 여객은 공항 키오스크에서 등록한다 | `/kiosk/register`. 등록 키오스크로 설치한 기기에서 열린다 |
| 기기를 쓰기 어려운 여객은 직원이 돕는다 | `/staff/desk/register`. 안내데스크 직원이 같은 질문을 대신 누른다. "직원이 대신 입력"으로 따로 센다 |
| 이름·연락처·진단명을 받지 않고, 안내가 달라지는 항목만 받는다 | 선택 항목은 `src/lib/catalog.ts`. 넣는 기준은 "이 답에 따라 기기가 보여주는 안내가 달라지는가" 하나다. 항목의 문구와 순서는 제안서 1단계 2)의 표와 같아야 한다 |
| 등록하면 QR과 번호가 있는 스티커를 받아 북클립에 붙여 여권에 끼운다 | 등록 키오스크의 「스티커 뽑기」. 가로 50mm, 세로 30mm 에 QR과 번호 여섯 자리만 찍는다. 항공편이나 고른 항목은 찍지 않는다 |
| 안내 키오스크·안내 로봇에 QR을 대면 화면이 여객에게 맞춰진다 | `/kiosk/guide`. QR을 카메라에 보여 주거나 번호를 누르면 큰 글씨·소리·그림·쉬운 말·영어가 그 자리에서 적용된다 |
| 여객에게 맞는 동선을 안내한다 (계단 없는 길, 쉬어 갈 곳) | `src/lib/airport.ts` 가 길을 계산한다. 위치 값은 모의 자료다(8장) |
| 도움이 필요하면 여객이 직원을 부른다. 직원이 먼저 다가가지 않는다 | 키오스크의 「직원 부르기」와 직원 호출 화면 `/staff`. 직원 화면에는 여객 목록이 없고 호출만 뜬다 |
| 출발 후 삭제한다 | 삭제 작업(`src/lib/purge.ts`). 여객은 휴대전화에서 직접 지울 수도 있다 |
| 기대 효과 세 가지와 확인 방법 | `src/lib/metrics.ts` 가 세고, `/staff/desk/stats` 가 같은 세 묶음으로 보여준다(5.3) |

**화면 설계 원칙 네 가지**

| 원칙 | 구현 |
|---|---|
| 한 화면에 질문 하나 | 등록은 일곱 화면이다. 한 화면에 질문 하나와 그 답만 둔다. 위에 "7단계 중 몇 단계"를 보여준다 |
| 글과 그림을 함께 | 고르는 항목마다 그림이 붙는다. 「글과 그림으로 보여주세요」를 고르면 그림이 커진다. 오류와 주의도 색만이 아니라 그림과 함께 보여준다 |
| 시간 제한 없이 여객의 속도로 | 화면을 말없이 끊지 않는다. 키오스크를 90초 동안 건드리지 않으면 "계속 이용하시겠어요?"를 묻고, 그 뒤 30초 동안 답이 없을 때만 처음 화면으로 돌아간다. 휴대전화 화면에는 이 확인이 없다 |
| 「직원 부르기」는 늘 같은 자리 | 키오스크의 모든 화면 오른쪽 위에 고정했다. 화면이 바뀌거나 글자가 커져도 자리가 같다. 「이전」과 「처음으로」는 왼쪽 위에 고정했다 |

## 3. 구성

| 역할 | 선택 | 비고 |
|---|---|---|
| 화면과 서버 | Next.js 15 (App Router, TypeScript), Vercel 배포 | 서울 리전 |
| DB | Supabase Postgres, 서울 리전 | 이 컴퓨터에서는 내장 DB(`.data/pglite`)를 쓴다 |
| 예약 실행 | `/api/cron/poll-flights`, `/api/cron/purge` | 지금은 Vercel Cron 으로 한 시간에 한 번. 호출에는 비밀 값이 필요하다 |
| QR 읽기 | 브라우저 카메라. 기기의 QR 판독 기능(BarcodeDetector)을 먼저 쓰고, 못 읽으면 jsQR 로 다시 읽는다 | 앱 설치 없음 |
| QR 그리기 | `qrcode` 라이브러리, 오류 정정 M, 둘레 여백 4칸 | |
| 소리 안내 | 브라우저에 들어 있는 읽기 기능(speechSynthesis) | 기기에 그 언어의 목소리가 있어야 한다 |
| 스티커 인쇄 | 브라우저의 인쇄 기능. 인쇄할 때만 50×30mm 스티커 모양이 나온다 | |

브라우저는 DB에 직접 접속하지 않는다. 모든 읽기·쓰기는 서버 경로(`/api/*`)를 거친다.

| 위치 | 내용 |

## 4. 화면 흐름

### 4.1 주소

| 주소 | 화면 | 열 수 있는 사람 |
|---|---|---|
| `/` | 첫 화면. 서비스 소개와 등록 시작. 오른쪽 위에서 영어로 바꾼다(`/?lang=en`) | 누구나 |
| `/register` | 등록 일곱 단계 | 누구나 |
| `/p/{token}` | 패스. QR이 가리키는 주소다 | QR 값을 아는 사람 |
| `/kiosk` | 키오스크 설치 | 누구나 열 수 있지만 설치 코드가 있어야 설치된다 |
| `/kiosk/register` | 등록 키오스크 | 키오스크로 설치한 기기 |
| `/kiosk/guide` | 안내 키오스크 | 키오스크로 설치한 기기 |
| `/staff/login` | 직원 접속 코드 입력 | 누구나 |
| `/staff/zone` | 근무 구역 고르기·바꾸기 | 공통 코드로 들어온 현장 직원 |
| `/staff` | 직원 호출 목록 | 직원 |
| `/staff/desk` | 안내데스크. 대신 등록, 패스 찾기 | 안내데스크 코드로 들어온 직원 |
| `/staff/desk/register` | 여객 대신 등록하기 | 안내데스크 |
| `/staff/desk/stats` | 오늘 현황 | 안내데스크 |

키오스크로 설치하지 않은 기기에서 `/kiosk/register` 나 `/kiosk/guide` 를 열면 `/kiosk` 로 보낸다. 로그인하지 않고 직원 화면을 열면 `/staff/login` 으로 보낸다.

### 4.2 등록 일곱 단계

휴대전화, 등록 키오스크, 안내데스크가 같은 질문을 같은 순서로 쓴다(`src/app/components/RegisterFlow.tsx`).

안내받는 방식을 맨 먼저 묻는다. 큰 글씨를 고른 여객이 바로 그 화면부터, 동의 글까지 큰 글씨로 보게 하기 위해서다.

| 순서 | 단계 | 묻는 것 | 그 답으로 달라지는 것 |
|---|---|---|---|
| 1 | 안내받는 방식 | 언어(한국어 / English)와 네 가지 방식. 여러 개를 고를 수 있고, 고르지 않아도 된다 | 고른 그 화면부터 바로 바뀐다. 안내 키오스크도 같은 방식으로 열린다 |
| 2 | 동의 | 무엇을 받는지, 어디에 쓰는지, 언제 지우는지, 무엇이 남는지 | 동의하지 않으면 "등록하지 않았습니다"와 함께 기존 안내와 지원을 그대로 받을 수 있다고 알리고 끝낸다 |
| 3 | 이동 | 이동할 때 불편한 점. 여러 개, 없으면 넘어간다 | 길 계산이 달라진다(아래 표) |
| 4 | 찾는 시설 | 자주 찾는 시설. 여러 개, 없으면 넘어간다 | 안내 화면에서 고른 시설이 맨 앞에 나온다 |
| 5 | 직원 도움 | 둘 가운데 하나. 고르지 않아도 된다 | 「필요할 때 직원을 부르고 싶습니다」를 고르면 「직원 부르기」 버튼이 커진다. 어느 쪽을 골라도 버튼은 늘 있다 |
| 6 | 항공편 | 편명. 두 글자 이상 넣으면 오늘과 내일 출발하는 편 가운데 그 글자로 시작하는 편을 여덟 편까지 보여준다. 정확히 같은 편명이 맨 위다. 편명을 모르면 도착 도시에서 고른다(아래) | 안내 화면의 항공편 판, 탑승구 가는 길, 삭제 시점 |
| 7 | 확인 | 고른 것을 한 화면에 보여준다. 묶음마다 「고치기」로 그 단계에 돌아간다 | 「등록하기」를 누르면 바로 패스가 나온다 |

항공편만 꼭 골라야 한다. 나머지는 고르지 않고 넘어갈 수 있다.

편명을 모르는 여객을 위한 길 (2026-10-10, 10-14 에 넣음)

- 입력란에 도착 도시 이름(도쿄), 영어 도시 이름(tokyo), 공항 코드(NRT), 편명의 숫자만(501) 넣어도 찾는다. 키오스크의 화면 글자판은 영문과 숫자뿐이라 편명, 숫자, 영어 도시 이름만 된다.
- 「편명을 모르겠어요 · 도착 도시에서 고르기」를 누르면 글자를 치지 않고 고른다. 많이 가는 곳 여덟 곳이 먼저 나오고, 도시 이름의 첫 글자(ㄱ, ㄴ … / 영어 화면은 A, B …)를 누르면 그 글자로 시작하는 도시가 나온다. 도시 목록은 오늘과 내일 남은 편이 있는 곳만이다(`/api/flights/destinations`).
- 같은 곳으로 가는 편이 여덟 편을 넘으면 출발 시간대(새벽·오전·오후·저녁)를 먼저 묻고, 그래도 여덟 편을 넘으면 항공사를 한 번 더 묻는다. 누르기 전에는 목록을 펼치지 않는다. 실제 자료에서 도쿄는 이틀에 180편, 한 시간대에 40편쯤이다.
- 소리 안내를 켠 여객에게는 이 단계가 바뀔 때마다 바뀐 내용(물음과 고를 것, 편 여섯 개까지)을 읽어 준다.
- 키오스크의 항공편 화면에서는 편을 고를 때까지 「다음」을 치워 둔다. 글자판과 도시 목록이 버튼에 가려지지 않게 하기 위해서다.

**선택 항목** (`src/lib/catalog.ts`)

| 묶음 | 코드 | 문구 | 안내에서 달라지는 것 |
|---|---|---|---|
| 안내받는 방식 | `gd_large` | 큰 글씨로 보여주세요 | 글자와 화면 전체가 1.25배로 커진다 |
| | `gd_voice` | 소리로 읽어주세요 | 화면이 바뀔 때마다 제목, 설명, 고를 것을 읽어 준다. 직원 호출 상태가 바뀔 때도 읽는다 |
| | `gd_picture` | 글과 그림으로 보여주세요 | 항목, 시설, 길 안내의 그림이 커진다 |
| | `gd_easy` | 쉬운 말로 알려주세요 | 질문과 안내 문구가 쉬운 말로 바뀐다 (예: "탑승 마감까지" → "비행기 타는 문이 닫히기까지") |
| 이동 | `mov_wheelchair_own` | 휠체어를 이용합니다 | 계단·에스컬레이터 없는 길, 느린 걸음으로 시간 계산, 가는 길의 장애인 화장실 표시 |
| | `mov_wheelchair_need` | 휠체어가 필요합니다 | 계단 없는 길, 느린 걸음. 시설 목록 맨 앞에 휠체어 빌리는 곳. 등록 화면에 "빌리는 곳을 안내해 드립니다. 예약은 아닙니다"를 붙인다 |
| | `mov_no_stairs` | 계단이나 에스컬레이터 이용이 어렵습니다 | 계단 없는 길, 느린 걸음 |
| | `mov_need_rest` | 오래 걷기 어려워 중간에 쉬어야 합니다 | 느린 걸음, 가는 길의 쉴 곳 표시 |
| | `mov_no_standing` | 오래 서 있기 어렵습니다 | 느린 걸음, 가는 길의 쉴 곳 표시 |
| 찾는 시설 | `fac_restroom` | 장애인 화장실 | 시설 목록 맨 앞, 가는 길에 있으면 표시 |
| | `fac_nursing` | 유아 휴게실·수유실 | 시설 목록 맨 앞, 가는 길에 있으면 표시 |
| | `fac_rest` | 쉴 곳 | 시설 목록 맨 앞, 가는 길에 있으면 표시 |
| | `fac_lounge` | 교통약자 라운지 | 시설 목록 맨 앞 |
| | `fac_calm` | 심리안정실 | 시설 목록 맨 앞 |
| 직원 도움 | `stf_call` | 필요할 때 직원을 부르고 싶습니다 | 「직원 부르기」 버튼이 커진다 |
| | `stf_self` | 스스로 이용하겠습니다 | 달라지는 것 없음. 버튼은 그대로 있다 |

- 영어를 고르면 여객 화면이 영어로 나온다. 운항 정보의 도착지 이름은 한국어뿐이라 영어 화면에서는 공항 코드(JFK 등)를 보여준다. 직원 화면은 한국어만 쓴다.
- 문구는 `src/lib/i18n.ts` 에 한국어, 영어, 그리고 각각의 쉬운 말이 있다.
- 소리 안내를 고르지 않아도, 기기가 읽기 기능을 지원하면 여객 화면 오른쪽 위에 「소리로 듣기」 버튼이 있다.
- 동의 글에는 "「직원 부르기」를 누르면 고르신 항목이 그 직원에게 전달됩니다"가 들어 있다.

### 4.3 패스

등록을 마치면 서버가 바로 패스를 만든다. 직원이 연결해 주는 단계는 없다.

| | 내용 |
|---|---|
| QR | 주소 `/p/{token}` 을 담는다. 항공편이나 고른 항목은 QR에 들어가지 않는다 |
| 번호 | 숫자 여섯 자리. 화면에는 "123 456"처럼 세 자리씩 띄워 보여준다. 카메라가 안 될 때 키오스크에 누른다 |

**휴대전화의 패스 화면 (`/p/{token}`)**

- 이 주소가 곧 패스다. 등록을 마치면 이 화면으로 넘어간다. 휴대전화 기본 카메라로 QR을 찍어도 이 화면이 열린다.
- 위에서부터 QR과 번호, 쓰는 방법, "홈 화면에 추가하거나 화면을 저장해 두세요", 내 항공편(탑승구, 출발 시각, 탑승 마감까지 남은 시간 추정), 고른 안내, 「내 등록 지우기」.
- 항공편은 1분마다 다시 받는다.
- 탑승구 가는 길과 가까운 시설은 나오지 않는다. 길은 키오스크가 놓인 자리를 기준으로 계산하기 때문이다.
- 「내 등록 지우기」를 누르고 한 번 더 확인하면 항공편과 고른 항목이 바로 지워지고, QR과 번호는 더 쓸 수 없다.
- 없는 QR 값이면 "등록된 패스가 아닙니다", 출발했거나 지운 패스면 "사용이 끝난 패스입니다"를 보여주고 새로 등록하는 길을 안내한다.

### 4.4 등록 키오스크 (`/kiosk/register`)

1. 처음 화면에 「등록 시작하기」와 「이미 등록했어요 (스티커 뽑기)」가 있다. 오른쪽 위에서 영어로 바꾼다.
2. 등록은 4.2의 일곱 단계와 같다. 화면이 크고, 편명은 화면의 글자판(ABC 순)으로 넣는다.
3. 마치면 QR과 번호가 화면에 나오고 「스티커 뽑기」로 인쇄한다. 설치할 때 "스티커 프린터가 연결되어 있습니다"를 켜 두었으면 마치는 즉시 인쇄를 시작한다.
4. 「이미 등록했어요」는 휴대전화로 등록한 여객을 위한 것이다. 휴대전화의 QR을 카메라에 보여 주면 같은 QR을 스티커로 뽑는다.
5. 「끝내기」를 누르거나 "계속 이용하시겠어요?"에 답이 없으면 처음 화면으로 돌아간다.

스티커는 가로 50mm, 세로 30mm 다. QR 한 변은 28mm 이고 그 옆에 번호가 찍힌다.

### 4.5 안내 키오스크 (`/kiosk/guide`)

한 페이지 안에서 처음 화면 → 안내 → 끝내기 → 처음 화면으로 돈다. 끝내면 앞사람의 내용은 화면에서 지운다.

**처음 화면**

- "QR을 카메라에 보여 주세요". 화면 쪽 카메라를 쓰고, 거울처럼 뒤집어 보여준다.
- QR이 없거나 안 읽히면 「고유 일련 번호 누르기」로 여섯 자리를 누른다. 다 누르면 바로 열린다.
- "패스가 없으신가요?" 안내와 영어 전환, 「직원 부르기」가 있다.

**안내 화면** (패스를 읽으면 그 여객의 언어와 방식으로 바뀐다)

| 위에서부터 | 내용 |
|---|---|
| 항공편 판 | 편명(공동운항이면 실제 운항 편명을 덧붙인다), 도착지, 출발 시각(지연이면 예정 시각에 줄을 긋고 바뀐 시각), 탑승구, 터미널, 탑승 마감까지 남은 시간. 남은 시간에는 "추정"을 붙인다. 30분 이하이면 붉게 보인다 |
| 탑승구 변경 알림 | 탑승구가 바뀌었으면 "탑승구가 112번에서 115번으로 바뀌었습니다" |
| 탑승구 가는 길 | 걸리는 시간과 거리, "계단 없는 길" 또는 "같은 층" 표시, 시간이 넉넉한지. 누르면 길을 한 줄에 한 가지씩 차례로 보여준다 |
| 길을 못 보여줄 때 | 그 까닭을 한 줄로 알린다(8.3) |
| 자주 찾는 시설 | 등록할 때 고른 시설이 먼저, 나머지는 "다른 시설"로 작게. 종류마다 가장 빨리 닿는 곳 하나씩. 누르면 그곳까지의 길 |
| 「안내 끝내기」 | 만족도 한 문항으로 넘어간다 |

- 걸리는 시간과 남은 시간을 견줘 세 가지로 알린다. 여유가 15분 이상이면 "시간이 넉넉합니다", 그보다 적으면 "지금 출발하시는 것이 좋습니다", 모자라거나 이미 탑승이 마감되었으면 "탑승 마감이 가깝습니다. 「직원 부르기」를 눌러 주세요".
- 안내를 보는 동안 30초마다 탑승구와 남은 시간을 다시 받는다. 탑승구가 바뀌면 길도 다시 계산한다. 보던 길이 없어졌으면 안내 첫 화면으로 돌려보낸다.
- 만족도는 "안내가 도움이 되었나요?" 한 문항이다. 「도움이 됐어요」「보통이에요」「도움이 안 됐어요」 가운데 하나를 누르거나 답하지 않고 끝낸다. 그 뒤 인사말을 잠깐 보여주고 처음 화면으로 돌아간다.
- 방금 끝낸 패스는 8초 동안 다시 읽지 않는다. 여객이 QR을 아직 들고 있어도 곧바로 다시 열리지 않게 하기 위해서다.
- 보안검색 전 구역에 놓인 키오스크에서는 탑승구 가는 길과 시설을 보여주지 않고 "보안검색과 출국심사를 지난 뒤, 안쪽 안내 키오스크에서 안내받으세요"라고 알린다.

**계속 이용 확인**

- 90초 동안 건드리지 않으면 "계속 이용하시겠어요?"를 묻는다. 남은 초를 보여주고, 까닭("다음 분이 내 정보를 보지 않게 하기 위해서입니다")을 적는다.
- 「계속 이용하기」를 누르면 그대로 이어진다. 30초 동안 답이 없거나 「끝내기」를 누르면 처음 화면으로 돌아간다.
- 처음 화면에 있을 때와, 직원을 불러 기다리는 동안에는 묻지 않는다.

### 4.6 직원 호출

직원은 패스를 지닌 여객에게 먼저 다가가지 않는다. 여객이 부를 때만 호출이 생긴다.

**키오스크 쪽**

1. 여객이 「직원 부르기」를 누르면 "직원을 부르고 있습니다. 이 자리에서 기다려 주세요"가 뜬다.
2. 직원이 받으면 "직원이 오고 있습니다"로 바뀐다. 키오스크는 3초마다 상태를 확인한다.
3. 직원이 마치면 "도움을 마쳤습니다"를 잠깐 보여주고 닫는다.
4. 여객은 「부르기 취소」로 거둘 수 있고, 「기다리면서 계속 보기」로 안내를 계속 볼 수 있다.

**규칙**

- 호출은 그 키오스크가 놓인 자리의 담당 구역으로 간다. 자리와 구역의 짝은 `src/lib/airport.ts` 의 `PLACES` 에 있다(모의 자료).
- 한 키오스크에서 끝나지 않은 호출은 하나뿐이다. 버튼을 여러 번 눌러도 한 줄만 생긴다.
- 패스를 찍은 뒤에 부르면 그 패스가 호출에 붙는다. 직원은 여객이 고른 항목과 항공편을 보고 온다. 패스 없이 부르면 "패스를 찍지 않고 불렀습니다. 가서 무엇이 필요한지 여쭤봐 주세요"가 보인다.
- 아무도 받지 않은 채 30분이 지난 호출은 스스로 닫힌다. 직원이 받은 호출은 받은 지 90분 뒤에 닫힌다.
- 이미 호출이 있는 키오스크에서 다른 사람이 다시 누르면, 호출에는 지금 누른 사람의 패스가 붙는다(패스 없이 눌렀으면 뗀다).

**직원 화면 (`/staff`)**

- 호출 목록만 있다. 받지 않은 호출이 맨 위에, 오래 기다린 순으로 놓인다. 5초마다 다시 읽는다.
- 호출마다 어느 키오스크인지, 등록하다가 불렀는지 안내를 보다가 불렀는지, 누른 시각과 지난 시간이 나온다.
- 「내 구역」과 「전체」를 바꿔 볼 수 있다. 다른 구역의 호출도 받을 수 있다.
- 「가겠습니다」를 누르면 받는다. 먼저 누른 쪽만 받는다. 「도움 마침」을 누르면 끝난다. 받지 않고 바로 마칠 수도 있다.
- 새 호출이 오면 진동과 짧은 소리로 알린다. 화면을 켜 두어야 한다. 화면을 꺼도 오는 알림은 없다.
- 끝난 호출은 30분 동안 "방금 끝난 호출"에 남는다.
- 기록에는 직원 개인이 남지 않고 구역만 남는다.

### 4.7 안내데스크 (`/staff/desk`)

안내데스크 코드로 들어온 직원만 쓴다. 호출 화면도 함께 쓴다.

| 기능 | 내용 |
|---|---|
| 여객 대신 등록하기 | 여객이 보는 것과 같은 질문을 직원이 여쭤보며 누른다. 동의 화면은 여객이 직접 읽거나 읽어 드린 뒤 넘어간다. 끝나면 스티커를 뽑는다. "직원이 대신 입력"으로 세고, 등록 완료 비율에는 넣지 않는다 |
| 패스 찾기 | 여객이 보여 준 QR을 찍거나 불러 준 번호 여섯 자리를 넣는다. 찾은 패스의 항공편과 고른 항목이 보인다 |
| 스티커 뽑기 | 찾은 패스의 같은 QR을 다시 인쇄한다 |
| 등록 지우기 | 여객이 지워 달라고 했을 때만 쓴다. 확인을 한 번 거치며 되돌릴 수 없다 |
| 오늘 현황 (`/staff/desk/stats`) | 5.3의 세 묶음을 오늘 날짜 기준으로 보여준다. 건수와 가운데값뿐이다 |

이름으로는 찾을 수 없다. 패스를 잃어버렸고 번호도 모르면 다시 등록한다.

### 4.8 키오스크 설치 (`/kiosk`)

1. 쓰임새를 고른다. 안내 키오스크 또는 등록 키오스크.
2. 놓을 자리를 고른다. 등록 키오스크는 보안검색 전 자리 3곳, 안내 키오스크는 그 뒤의 자리 14곳이 나온다. 자리 목록은 모의 자료다.
3. 등록 키오스크는 스티커 프린터가 연결되어 있는지 표시한다.
4. 설치 코드를 넣는다. 맞으면 그 기기가 30일 동안 키오스크로 동작한다.

- 키오스크로 설치한 기기는 직원 화면을 열 수 없다. 직원 코드로는 키오스크를 설치할 수 없고, 설치 코드로는 직원 화면에 들어갈 수 없다.
- 카메라가 둘 이상이면 화면에서 바꿀 수 있고, 고른 카메라를 기기가 기억한다.

| consent_at | 동의 시각 |
| started_at, submitted_at | 등록 화면을 연 시각, 마친 시각 |
| edit_count | 앞 단계로 돌아가 값을 바꾼 횟수. 저장만 하고 집계에는 아직 쓰지 않는다 |
| status | `pending`(패스 만들기 전) / `active` / `expired`(출발 후 삭제) / `revoked`(여객이 지움) |
| is_mock | 모의 데이터 여부 |

`name`, `categories`, `receipt_no` 칸은 예전 구조의 것이다. 테이블에 남아 있지만 쓰지 않는다.

**passes (패스)**

| 항목 | 내용 |
|---|---|
| token | QR에 담기는 값 16자 |
| pass_no | 번호 여섯 자리 |
| registration_id | 연결된 등록. 지운 뒤에는 비운다 |
| state | `active`(사용 중) / `expired`(출발 후 끝남) / `revoked`(여객이 지움). 끝난 패스는 다시 쓰지 않는다 |

**calls (직원 호출)**

누른 시각, 키오스크 자리, 담당 구역, 등록(패스를 찍고 불렀을 때), 어느 화면에서 불렀는지(`register` / `guide`), 받은 시각과 받은 구역, 끝난 시각, 끝난 방식(`done` 도움 마침 / `cancelled` 여객이 거둠 또는 시간이 지나 닫힘).

**events (건수 기록)**

| kind | 뜻 | 누가 적는가 |
|---|---|---|
| `reg_start` | 등록의 첫 질문을 넘겼다 | 화면이 보낸다. 직원이 대신 넣는 등록은 보내지 않는다 |
| `reg_done` | 등록을 마쳤다 | 서버가 적는다. 직원이 대신 넣은 등록은 적지 않는다 |
| `guide_open` | 안내 키오스크에서 패스를 열었다 | 서버가 적는다 |
| `survey` | 만족도 응답. 값 3(도움이 됐어요) / 2(보통이에요) / 1(도움이 안 됐어요) | 화면이 보낸다 |

함께 남는 것은 시각, 경로(`web` / `kiosk`), 안내 방식을 하나라도 켰는지, 키오스크 자리, 남용을 막는 데 쓰는 기기 표시(접속 주소와 브라우저 표시를 해시한 값)다. 등록이나 패스와는 연결되지 않는다.

**flights (운항), flight_polls (수집 기록)** 7장 참고.

**zones (직원 구역과 접속 코드)**

구역 이름, 터미널, 탑승구 목록, 접속 코드(해시로 저장), 안내데스크 여부. 구역이 아닌 자리가 두 개 있다. `staff-common`(현장 직원 공통 코드)과 `kiosk`(키오스크 설치 코드)다. `facilities` 칸은 쓰지 않는다. 시설 위치는 `src/lib/airport.ts` 에 있다.

**access_logs (기록)**

시각, 구역, 기기 표시(해시), 행위. 지금 적는 행위는 `register`(등록), `cancel`(등록 지움), `login_fail`(접속 코드 틀림), `number_fail`(고유 일련 번호 틀림) 네 가지다.

### 5.2 보관과 삭제

**언제 지우는가** (`src/lib/journey.ts`, `src/lib/purge.ts`)

| 시점 | 처리 |
|---|---|
| 운항 정보의 상태가 출발로 바뀜 | 바로 지울 대상이 된다 |
| 변경 출발 시각(없으면 예정 출발 시각) + 30분 | 지울 대상이 된다 |
| 결항 | 예정 출발일 다음 날 04:00 까지 남긴다. 여객이 공항에 머물 수 있어서다 |
| 예정 출발 시각 + 24시간 | 위 조건과 상관없이 지운다 (안전장치) |
| 운항 정보가 사라진 등록 | 등록 후 48시간 |
| 패스를 만들다 실패해 남은 등록 | 등록 후 24시간 |
| 여객이 「내 등록 지우기」를 누름, 안내데스크가 「등록 지우기」를 누름 | 바로 지운다 |
| 건수 기록, 직원 호출, 조회 기록, 수집 기록 | 90일 후 행을 지운다 |
| 운항 정보 | 예정 출발 3일 후 지운다 |

삭제 작업은 예약 실행으로 돈다(지금은 한 시간에 한 번). 작업이 늦게 돌아도, 패스를 여는 쪽이 같은 기준으로 끝난 패스를 열지 않는다. 그래서 떠난 여객의 QR을 대도 "사용이 끝난 패스입니다"가 나온다.

**무엇을 지우고 무엇을 남기는가**

"지운다"는 등록 행을 없애는 것이 아니라, 여객이 입력한 값을 비우고 다른 기록과의 연결을 끊는 것이다. 동의 화면의 문구는 이 표와 같아야 한다.

| 대상 | 지우는 것 | 남는 것 |
|---|---|---|
| 등록 | 항공편(편명과 날짜), 고른 항목 | 등록 경로, 화면 언어, 동의·시작·제출 시각, 고친 횟수, 모의 표시. 상태는 `expired` 또는 `revoked` |
| 패스 | 등록과의 연결 | QR 값, 번호, 끝난 상태. 끝난 패스의 번호는 새 패스가 다시 쓸 수 있다 |
| 직원 호출 | 등록과의 연결. 끝나지 않은 호출은 닫는다 | 키오스크 자리, 구역, 누른·받은·끝난 시각 |
| 조회 기록 | 등록과의 연결 | 시각, 구역, 기기 표시(해시), 행위 |
| 건수 기록 | 처음부터 등록과 연결되지 않는다 | 그대로 (90일) |

남는 값만으로는 누구의 것인지 알 수 없다. 다만 여객이 아주 적은 시간대에는 등록 시각과 호출 시각·자리로 짐작할 여지가 있다. 이 점은 기관의 개인정보 검토에서 확인받는다.

### 5.3 측정값

제안서의 "기대 효과와 확인 방법" 세 가지를 아래 숫자로 센다(`src/lib/metrics.ts`).

| 기대 효과 | 세는 숫자 | 어디서 나오는가 |
|---|---|---|
| 1. 여객이 자신에게 맞는 안내를 받는다 | 안내 화면을 연 횟수. 만족도 응답 수와 세 가지 답의 수 | `events` 의 `guide_open`, `survey` |
| 2. 기기를 쓰기 어렵던 여객도 스스로 이용한다 | 안내 방식을 켠 여객과 켜지 않은 여객의 등록 완료 비율(첫 질문을 넘긴 사람 가운데 마친 사람). 등록 작성 시간의 가운데값 | `events` 의 `reg_start`, `reg_done`. 작성 시간은 `registrations` 의 제출 시각 − 시작 시각 |
| 3. 직원의 업무 부담을 늘리지 않는다 | 「직원 부르기」를 누른 횟수(등록하다가 / 안내를 보다가), 도움 마침·여객이 거둠·열려 있는 호출 수, 누른 뒤 직원이 받기까지 걸린 시간의 가운데값. 직원이 대신 입력한 등록 수 | `calls`, `registrations` 의 경로 |

- 완료 비율과 작성 시간은 여객이 스스로 한 등록만 센다. 직원이 대신 넣은 것은 건수로만 남는다.
- "안내 방식을 켰다"는 큰 글씨, 소리, 글과 그림, 쉬운 말 가운데 하나라도 고른 것이다. 첫 질문을 넘길 때의 값으로 시작과 완료를 함께 센다.
- "직원이 받기까지"는 직원이 「가겠습니다」를 누른 시각까지다. 직원이 실제로 도착한 시각은 웹이 알 수 없다.
- 안내데스크의 오늘 현황은 오늘(한국 날짜) 것만, 운영자용 명령(`scripts/remote-metrics.ts`)은 최근 14일(바꿀 수 있다)을 같은 방식으로 센다.
- 웹이 세지 못하는 것은 현장 관찰로 본다. 키오스크 앞에서 그만둔 까닭, 직원이 도운 내용과 걸린 시간이 여기에 해당한다.

### 5.4 QR 값과 번호의 규칙 (`src/lib/pass-format.ts`, `src/lib/passes.ts`)

| | QR 값 | 번호 |
|---|---|---|
| 모양 | 대문자와 숫자 16자. 헷갈리는 글자 I, L, O, U 는 쓰지 않는다 | 숫자 여섯 자리 |
| 만드는 방법 | 서버가 무작위로 뽑는다 (80비트) | 000000~999999 에서 무작위 |
| 겹치면 안 되는 범위 | 전체 | 살아 있는 패스끼리. 끝난 패스의 번호는 다시 쓴다 |
| 겹쳤을 때 | 다시 뽑는다. 30번 해도 안 되면 "패스를 만들지 못했습니다. 잠시 후 다시 시도해 주세요" | 같음 |
| 누가 쓸 수 있는가 | 값을 아는 사람은 누구나 패스 화면을 연다 | 키오스크와 안내데스크에서만 넣을 수 있다 |

**QR 주소를 전부 대문자로 만드는 까닭**

- QR에 넣는 주소는 `HTTPS://.../P/XXXXXXXXXXXXXXXX` 처럼 전부 대문자다.
- 대문자와 숫자만 있으면 QR이 영숫자 방식으로 담아 칸 수가 줄어든다. 배포 주소 기준으로 가로세로 29칸이다.
- 칸 수가 적으면 같은 크기로 찍어도 한 칸이 커져 카메라가 잘 읽는다. 스티커의 QR 28mm 에서 한 칸이 약 0.75mm 다.
- 대문자 주소 `/P/...` 로 들어온 요청은 서버가 `/p/...` 로 받아 준다(`next.config.ts`). 소문자로 바뀐 주소를 읽어도 같은 패스가 열린다.

**번호 입력의 잠금**

- 번호는 여섯 자리라 맞혀 볼 수 있다. 그래서 키오스크로 설치한 기기와 안내데스크에서만 받는다.
- 같은 기기에서 10번, 또는 같은 접속 주소에서 20번 틀리면 10분 동안 번호 입력을 받지 않는다. 공용 기기라 여러 여객의 실수가 쌓이므로 접속 코드(5번)보다 넉넉하게 두었다.
- 출발했지만 아직 지워지지 않은 패스의 번호도 없는 번호와 똑같이 "등록된 패스가 아닙니다"로 답한다. 이 경우는 틀린 횟수로 세지 않는다.
- 번호로는 사용 중인 패스만 찾는다. 끝난 패스가 있었는지는 알려 주지 않는다.

## 6. 접근 통제

### 6.1 누가 무엇을 열 수 있는가

| 누구 | 열 수 있는 것 | 열 수 없는 것 |
|---|---|---|
| 아무나 | 첫 화면, 등록, 편명 검색(편명·도착지·출발 시각만. 탑승구는 주지 않는다) | 그 밖의 모든 것 |
| QR 값만 아는 사람 | 그 패스의 화면: QR, 번호, 항공편과 탑승구, 고른 항목. 그 등록을 지울 수 있다 | 다른 패스. 탑승구 가는 길과 가까운 시설(키오스크에서만 나온다) |
| 번호만 아는 사람 | 없음. 키오스크나 안내데스크에 가서 눌러야 한다 | |
| 키오스크 (설치 코드로 설치한 기기) | 등록 받기, QR이나 번호로 패스 열기, 그 자리 기준의 길과 시설, 자기 자리에서 만든 호출의 상태 보기와 거두기 | 직원 화면 전체. 다른 키오스크의 호출 |
| 현장 직원 (공통 코드 → 구역 선택) | 호출 목록(전 구역), 받기와 마치기. 패스를 찍고 부른 호출에서는 그 여객의 고른 항목(줄인 말)과 항공편 | 패스 찾기, 대신 등록, 오늘 현황. 호출하지 않은 여객의 정보는 볼 길이 없다 |
| 안내데스크 (안내데스크 코드) | 현장 직원이 하는 것 전부. 대신 등록, QR이나 번호로 패스 찾기, 스티커 다시 뽑기, 등록 지우기, 오늘 현황 | 운영자 통로 |
| 운영자 (서버의 비밀 값 `CRON_SECRET` 을 아는 사람) | 초기 설정(`/api/admin/setup`), 시연용 패스 만들기(`/api/admin/demo`, 모의 데이터 모드에서만), 측정값 내려받기(`/api/admin/metrics`), 예약 실행 경로 | |

패스의 QR 값은 등록한 쪽에만 한 번 돌려준다. 그 뒤에는 QR을 찍거나 번호를 넣은 키오스크·안내데스크에만 돌려준다(스티커를 다시 뽑는 데 쓴다).

### 6.2 규칙과 기본값 (`src/lib/config.ts`)

| 규칙 | 기본값 |
|---|---|
| 직원 로그인 | 접속 코드. 현장 직원 공통 코드로 들어와 근무 구역을 고르고 근무 중에 바꿀 수 있다. 안내데스크는 안내데스크 코드를 쓴다. 구역마다 따로 있는 코드로도 들어올 수 있으며 그때는 구역을 바꿀 수 없다 |
| 직원 로그인 유지 | 12시간. 구역을 바꿔도 늘어나지 않는다. 구역을 고르기 전에는 호출 목록이 열리지 않는다 |
| 키오스크 설치 유지 | 30일 |
| 접속 코드·설치 코드 입력 실패 | 같은 기기에서 5번, 또는 같은 접속 주소에서 20번 틀리면 10분 차단 |
| 고유 일련 번호 입력 실패 | 위와 같은 기준 |
| 여객 등록 | 휴대전화 등록은 같은 접속 주소에서 10분에 20건까지. 키오스크와 안내데스크는 한 기기로 여러 명을 받으므로 막지 않는다 |
| 건수 기록 | 같은 접속 주소에서 10분에 200건까지 |
| 키오스크의 계속 이용 확인 | 90초 뒤에 묻고, 30초 동안 답이 없으면 처음 화면 |
| 직원 화면이 호출을 다시 읽는 간격 | 5초 |
| 안내 화면이 탑승구와 남은 시간을 다시 읽는 간격 | 30초 |

- 직원은 개인이 아니라 구역으로만 구분한다. 로그인 정보에도 구역만 담는다.
- 기기는 접속 주소와 브라우저 표시를 해시한 값으로 구분한다. 원래의 접속 주소는 저장하지 않는다.
- 모든 화면은 다른 사이트의 틀 안에 넣을 수 없게 했고, 패스 주소가 다른 사이트로 가는 요청에 실려 나가지 않게 했다(`next.config.ts`).
- 기본값은 기업탐방에서 기관 기준을 확인한 뒤 설정값만 바꾼다.

## 7. 운항 정보 연동

### 7.1 수집

- 대상: 공공데이터포털 인천국제공항공사 여객기 운항 현황 상세 조회 서비스, 출발편
- 주기: 목표는 5분. 지금 걸려 있는 것은 한 시간에 한 번이다(14장)
- 범위: 오늘과 내일(한국 날짜)
- 편을 구분하는 기준은 예정 출발의 한국 날짜와 편명이다. 이 둘이 같으면 같은 편으로 보고 그 행만 갱신한다.
- 수집은 행을 지우지 않는다. 응답에 없는 편은 그대로 둔다. 오래된 편은 삭제 작업이 예정 출발 3일 뒤에 지운다.
- 갱신하는 항목은 공동운항의 실제 운항 편명, 항공사, 도착지, 터미널, 탑승구, 예정·변경 출발 시각, 상태 문구다.
- 탑승구가 이전 값과 다르면 이전 탑승구와 변경 시각을 남긴다. 미정에서 처음 배정된 것은 변경으로 보지 않는다.
- 응답에서 탑승구가 비어 오면 알고 있던 탑승구를 지우지 않는다.
- 받지 못하거나 오늘·내일 출발편이 0건이면 그 회차를 실패로 보고 아무것도 갱신하지 않는다.
- 매 실행 결과를 `flight_polls` 에 기록한다.

### 7.2 화면 표시

항공편은 안내 키오스크와 휴대전화의 패스 화면에 같은 모양으로 나온다.

| 상황 | 표시 |
|---|---|
| 정상 | 편명, 도착지, 출발 시각, 탑승구, "탑승 마감까지 N분 (추정)" |
| 마지막 수집 성공이 수집 간격 + 15분보다 오래됨, 또는 수집한 적이 없음 | "운항 정보가 늦어지고 있습니다. 탑승구는 전광판에서 한 번 더 확인해 주세요" |
| 탑승구 미정 | 탑승구 자리에 "미정". 길 대신 "탑승구가 아직 정해지지 않았습니다" |
| 탑승구 변경 | "탑승구가 A번에서 B번으로 바뀌었습니다" |
| 지연 | 예정 시각에 줄을 긋고 바뀐 시각을 보여준다 |
| 결항 | "결항된 편입니다. 항공사에 확인해 주세요". 남은 시간과 길은 보여주지 않는다 |
| 운항 정보를 찾지 못함 | "운항 정보를 받지 못했습니다. 전광판을 확인해 주세요" |

### 7.3 계산

- 탑승 마감 추정 = 변경 출발 시각(없으면 예정 출발 시각) − 10분. 10분은 설정값이다. 공공데이터에 탑승 마감 시각이 없어서 쓰는 추정값이며 화면에 "추정"이라고 적는다.
- 상태가 `탑승마감`이면 추정 대신 "탑승이 마감되었습니다"로 표시한다.
- 상태가 `탑승중` 또는 `마감예정`이면 남은 시간 앞에 "지금 탑승 중입니다"를 붙인다.
- 추정 마감 시각이 지났으면 "탑승 마감 시각이 지났습니다 (추정)".
- 공동운항: 여객이 고른 편명이 공동운항 편명이면 실제 운항 편의 탑승구·시각·상태를 쓴다. 화면에는 여객이 고른 편명을 보여주고 운항 편명을 덧붙인다.

### 7.4 직원 구역

구역은 직원이 근무 구역을 고르고, 키오스크의 호출이 어느 구역으로 갈지 정하는 데 쓴다.

| 터미널 | 구역 | 근거 |
|---|---|---|
| 탑승동 | 중앙부 / 중간 / 끝단 | 임시값. 탑승구 번호가 중앙에서 먼 순서로 나눴다 |
| 제2여객터미널 | 다섯 구역 | 팀의 운항 조회 웹 `zones.json` 의 값 |
| 제1여객터미널 | 세 구역 | 탑승구 번호 순서로 나눈 추정치. 이름에 "경계 추정"을 붙였다 |

## 8. 길과 시설 안내

### 8.1 지금 쓰는 자료는 모의 자료다

`src/lib/airport.ts` 의 위치와 거리는 모두 시연용으로 지어낸 값이다. 실제 공항의 거리, 시설 위치, 엘리베이터 위치와 다르다. 화면에도 "길과 시설 위치는 시연용 모의 자료입니다"라고 적는다.

계산하는 방법(가까운 시설 고르기, 계단 없는 길, 걷는 속도)은 자료가 바뀌어도 그대로 쓴다.

### 8.2 모의 자료의 모델

| 항목 | 정한 값 |
|---|---|
| 터미널의 모양 | 탑승구가 한 줄로 늘어선 것으로 본다. 탑승구 번호로 위치를 정한다 |
| 탑승구 범위와 간격 | 제1여객터미널 1~50번 22m, 탑승동 101~132번 30m, 제2여객터미널 208~291번 14m |
| 층 | 탑승구는 3층. 교통약자 라운지는 4층. 셔틀트레인 승강장은 지하 1층 |
| 층을 옮기는 곳 | 구역마다 세 곳. 엘리베이터와 에스컬레이터가 함께 있다. 걷는 거리가 가장 짧아지는 곳을 고른다 |
| 걷는 속도 | 보통 걸음 1분에 70m. 이동 항목을 하나라도 고른 여객은 1분에 45m |
| 층을 옮기는 시간 | 엘리베이터 3분(기다리는 시간 포함), 에스컬레이터 1분 |
| 계단 없는 길 | 휠체어 이용, 휠체어 필요, 계단 어려움 가운데 하나를 골랐으면 엘리베이터만 쓴다. 아니면 에스컬레이터를 쓴다 |
| 셔틀트레인 | 제1여객터미널에서 탑승동으로 갈 때만. 기다리는 시간을 넣어 7분 |
| 시설 | 장애인 화장실, 유아 휴게실·수유실, 쉴 곳, 교통약자 라운지, 심리안정실, 휠체어 빌리는 곳. "N번 탑승구 옆"으로 위치를 적는다 |
| 가는 길의 시설 | 걷는 구간마다 세 곳까지. 고른 항목에 따라 쉴 곳, 장애인 화장실, 수유실을 알린다 |
| 가까운 시설 | 같은 구역 안에서 종류마다 가장 빨리 닿는 곳 하나 |
| 키오스크 자리 | 보안검색 전 3곳(등록용), 그 뒤 14곳(안내용). 자리마다 호출을 받는 직원 구역이 정해져 있다 |

15m 보다 짧은 걸음은 따로 적지 않는다.

### 8.3 길을 안내하지 못하는 경우

| 경우 | 화면에 나오는 말 |
|---|---|
| 탑승구가 아직 정해지지 않았거나 터미널을 모름 | "탑승구가 아직 정해지지 않았습니다. 정해지면 이 화면과 전광판에 나옵니다" |
| 보안검색 전 구역의 키오스크 | "보안검색과 출국심사를 지난 뒤, 안쪽 안내 키오스크에서 탑승구 가는 길을 안내받으세요" |
| 걸어서 갈 수 없는 다른 터미널 (제1여객터미널 → 탑승동 말고는 모두) | "이 항공편은 다른 터미널에서 출발합니다. 「직원 부르기」를 눌러 주세요" |
| 결항 | "결항된 편이라 탑승구 가는 길을 안내하지 않습니다" |
| 키오스크가 아님 (여객 휴대전화) | 길과 시설을 보여주지 않는다 |

### 8.4 실제 자료로 바꿀 때 필요한 것

- 키오스크와 안내 로봇이 놓인 자리, 그리고 자리마다 호출을 받을 직원 구역
- 교통약자 시설의 실제 위치와 층 (장애인 화장실, 수유실, 쉴 곳, 라운지, 심리안정실, 휠체어 대여)
- 엘리베이터·에스컬레이터의 위치와, 구간 사이의 실제 걷는 거리 (실내 지도)
- 터미널 사이를 옮기는 방법과 걸리는 시간
- 걷는 속도와 엘리베이터 대기 시간의 기준

자료를 받으면 `src/lib/airport.ts` 의 값을 바꾼다. 한 줄로 늘어선 모양으로 표현할 수 없는 구조라면 위치를 정하는 방식도 함께 고쳐야 한다.

- 화면 점검은 개발 컴퓨터의 서버와 모의 운항으로 돈다. 준비 순서는 `scripts/e2e.ts` 맨 위와 README 에 있다.
- 화면 점검의 카메라 QR 읽기는 패스 QR 그림을 가짜 카메라 영상으로 넣어 확인한다.
- 접근성 자동 점검은 대비·이름표·역할 같은 것만 잡는다. 화면 읽기 프로그램으로 실제로 써 보는 것을 대신하지 않는다.
- "계속 이용하시겠어요?"는 개발 서버에서만 주소에 `?idle=초` 를 붙여 기다리는 시간을 줄여 점검한다. 배포된 곳에서는 이 값이 듣지 않는다.

**2026-10-10: 가상 이용자로 눌러 보고 고침, 제안서와 용어를 맞춤**

- 화면의 "패스 번호"를 제안서의 말인 "고유 일련 번호"로 바꿨다.
- 작은 휴대전화에서 글자를 키워도 위쪽 줄이 한 줄에 들어오게 했다. 동의 화면의 버튼을 글 끝으로 옮겼다(글이 길면 끝까지 내려가야 나온다).
- 「설정」에서 바꾼 글자 크기가 등록에서 고유 일련 번호 화면으로 이어지게 했다(탭 안에만 기억한다).
- 편명을 몰라도 도착 도시 이름이나 숫자로 찾게 했다. 안내 키오스크 처음 화면에 휴대전화로 찍어 등록하는 QR 을 넣었다. 다른 터미널 편은 어느 터미널인지 알린다. 영어 화면의 도착지를 도시 이름으로 보여준다.

**2026-10-14: 도착 도시 고르기, 태블릿, 키보드와 소리 안내**

- 도착 도시를 눌러 고르는 화면과 출발 시간대·항공사로 좁히는 단계를 넣었다(4.2).
- 태블릿 크기(1024×768, 768×1024 등)의 키오스크에서 질문과 글자판이 「다음」 버튼에 가려지지 않게 여백을 줄였다. 동의 버튼은 키오스크에서도 글 끝에 둔다.
- 키보드만으로 등록을 끝낼 수 있는지 눌러 보고 고쳤다: 화면 위에 뜬 창 안에 초점을 가둔다, 도시 고르기를 열고 닫을 때 초점을 옮긴다, 가려진 항목으로 초점이 가면 화면에 올린다, 하나만 고르는 묶음은 화살표 키로 옮긴다.
- 고유 일련 번호 화면을 보는 동안 휴대전화 화면이 꺼지지 않게 했다(지원하는 기기에서만).
- 운영자가 "여러 번 틀려 잠김"을 푸는 설정을 넣었다(`/api/admin/setup` 에 `clearLocks`). 화면 점검도 시작할 때 이것으로 앞선 실행의 틀린 기록을 지운다.
- 배포된 곳에서 실제 편 여섯 개로 등록해 실제 탑승구와 터미널, 공동운항의 실제 운항 편명, 탑승구 변경 안내가 고유 일련 번호 화면에 나오는 것을 확인하고 바로 지웠다.
- 고유 일련 번호 화면을 인터넷이 끊겨도 열리게 했다(`public/sw.js`, 운영 빌드에서만 켜짐). 인터넷이 되면 새로 받고, 끊겼거나 3초 안에 답이 없으면 휴대전화에 남겨 둔 화면을 보여 준다. 「내 등록 지우기」를 누르면 바로 지우고, 남긴 지 36시간이 지나면 지운다. 다른 화면과 API 는 건드리지 않는다.
- 손이 떨려 같은 버튼을 두 번 누르면 동의 화면과 확인 화면을 건너뛰던 것을 막았다. 사람이 눌러 화면이 바뀐 직후 0.5초 안의 두 번째 누름은 무시한다(`FlowShell`).
- 키오스크 처음 화면(안내·등록)에 큰 「소리로 안내 듣기」 버튼을 두었다. 켜 두면 QR 을 댄 뒤에도 계속 읽어 준다.
- 키오스크에서 번호를 틀린 뒤 오류 문구가 사라져도 번호판이 움직이지 않게 그 자리를 비워 둔다.
- 보안: 잠금 한도는 시도를 먼저 기록하고 센 뒤에 확인한다(`claimAttempt`). 한꺼번에 많이 보내도 한도를 넘는 시도는 확인하지 않는다. IPv6 는 /64 로 묶어 센다. 로그인 코드 대조는 비동기로 한다. 휴대전화 등록은 모든 주소를 합해 10분에 300건까지 받는다. 초기 설정은 여섯 자리보다 짧은 접속 코드를 받지 않는다.
