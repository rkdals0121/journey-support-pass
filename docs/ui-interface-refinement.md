# 공항 이용 지원 UI 개편

## 문제와 적용 기준

같은 카드·배지·둥근 테두리·설명 문단을 여객, 직원, 현장 기기와 체크리스트에서 반복하고 있었다. 화면의 용도를 시각적으로 구분하기 어렵고 실제 작업보다 장식과 반복 안내를 먼저 읽게 되는 문제가 있었다.

색상은 기존 초록·민트와 해바라기 로고를 유지한다. 노란 시범운영 띠는 다시 넣지 않는다.

| 참고 사례 | 확인한 원칙 | 적용 |
|---|---|---|
| [KRDS 디자인 스타일](https://www.krds.go.kr/html/site/style/style_01.html) | 색상·타이포그래피·레이아웃·컴포넌트의 일관된 기준 | 공통 글자 크기, 선, 모서리와 간격을 정하고 화면 용도별로 배치 |
| [온통청년](https://www.youthcenter.go.kr/) | 검색과 서비스 탐색을 별도로 제공 | 여객 홈에서 검색과 실제 서비스 목록을 앞에 배치 |
| [GOV.UK Task list](https://design-system.service.gov.uk/components/task-list/) | 필요한 작업과 완료 상태가 식별되는 목록 | 체크리스트를 줄 단위 선택 목록으로 정리하고 체크 상태와 초점을 보존 |
| [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/) | 확인 화면에서 항목명과 값을 구분 | 요청 확인·내역은 항목과 상태 중심으로 유지 |
| [IBM Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) | 구조화된 데이터의 열 정렬, 탐색과 상세 작업 분리 | 직원 화면은 표·필터·상세 영역을 중심으로 구성 |

디자인 적용은 위 사례를 바탕으로 한 이 프로젝트의 판단이며, 해당 기관의 인증이나 사용성 검증을 받은 것은 아니다.

## 화면별 변경

- 여객 홈·서비스: 가짜 탑승구/이동 경로 그래픽 제거. 검색과 간단한 서비스 설명을 노출. PC는 3열, 휴대전화는 가로형 항목을 세로로 나열한다.
- 현장 도움 요청: 서비스 이름을 반복하던 선택 요약을 제거하고 서비스 변경 링크만 남김. 입력 영역을 겹겹의 카드에서 구분선 중심으로 정리.
- 내 요청: PC에서는 상태·서비스·위치·진행 확인을 정렬하고 휴대전화에서는 좁은 폭에 맞게 재배치.
- 사전등록: 항공편 연결 진입 기능을 유지하면서 설명과 등록 순서를 분리.
- 체크리스트: 그림자와 카드 테두리를 줄이고 선택한 행을 초록색 선과 배경, 체크 표식으로 구분. 하단 버튼이 선택 항목을 덮지 않게 내용 뒤에 배치.
- 직원: 흰 탐색 영역과 초록색 현재 메뉴 표시. 접수 표의 글자·행 간격을 조정. 상세 화면 진입 시 불필요한 흐려짐 제거.
- 키오스크: 큰 제목·버튼과 읽기 영역을 가로로 분리. 장식용 QR 아이콘을 탑승권 인식 설명으로 교체. 미리보기임을 명확히 유지.
- 로봇: 세로 화면 구조 유지. 말풍선과 과한 테두리 축소, '저를 깨워 주세요' 대신 실제 행동을 안내하는 문구 사용.
- 기기 점검: 상태 행 위주로 정리하고 더 이상 사용하지 않는 스티커 인쇄 안내 삭제.
- 모션: 색상·테두리 변화 정도로 제한하고 모션 줄이기 설정을 존중.

## 기능 변경과 합치는 방법

기준 커밋: 686814a (PR #30까지 포함).
브랜치: design/airport-ui-system

업무 API·데이터베이스·배정·권한·토큰 로직은 변경하지 않는다. 디자인 규칙은 src/app/interface.css에 모으고 layout.tsx에서 마지막에 불러온다. 공통 기능 파일인 HelpFlow.tsx의 차이는 제목·서비스 변경 링크·중복 표시 제거에 한정한다. 전체 파일 재포맷은 하지 않는다.

다른 기능 브랜치를 합칠 때 새로 생긴 입력·버튼·상태가 이 스타일 범위에서 정상 표시되는지 미리보기에서 확인해야 한다. 이후 새 컴포넌트에도 별도 확인이 필요하며, 모든 미래 변경의 디자인 보존을 자동 보장하지는 않는다.

운영 배포는 사용자 확인 후 진행한다.
