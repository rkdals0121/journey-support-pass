# 전체 화면 디자인 진단

기준 커밋: 5e7f5d6fb618120c94930f21b398d463ffab1dc2. 기능/API/데이터/화면 순서는 이번 변경 대상이 아니다.

## 우선 진단
- 9개 전역 스타일 파일을 순서대로 겹쳐 읽는다. globals → redesign → service-flow → staff-console → airport-design → booking → feedback-refinements → interface → task-experience. 같은 버튼·화면 틀의 규칙을 여러 파일에서 덮어쓴다.
- 숫자·여백·모서리·직접 색상·모션을 전역 토큰으로 통제하지 못한다. 임의의 650/750 굵기, 작은 보조 문구, 반복 경고 배경이 정보 위계를 흐린다.
- 여객은 읽기·선택·입력·확인의 역할이 구별되어야 한다. 키오스크는 넓고 낮은 화면과 좁고 긴 화면을 따로 구성해야 한다. 직원은 지금 처리할 목록과 선택한 한 건이 우선이다.
- 스탬프·인쇄·오류까지 동일한 글자/색/간격/포커스 기준이 필요하다. 삽화 색도 전역 토큰으로 관리하되 정보 바코드의 검정/흰색은 machine-ink/paper 역할로 분리한다.

## 기준 화면
`design-before-after/before/manifest.json`에 모든 경로·크기·응답·제목·넘침·주요 버튼 수를 기록한다. 개인 URL은 격리된 테스트 등록이며 manifest에서는 [token]/[receipt]로 익명화한다.

## 반복 부품
버튼(주/보조/텍스트), 입력/선택/키패드, 단계, 상태 알림, 카드/리스트/표, 항공편·탑승구 표지, 도구 머리말, 고정 하단 행동, 직원 도움, 빈 목록/연결 오류/인쇄 표지.

## 단계 PR
1. 토큰·스타일 구조·부품 전시장
2. 여객·등록·안내·예약·시연·스탬프 화면
3. 키오스크·로봇·직원 화면
4. 모션·인쇄·접근성·전체 전후 비교

병합은 요청자가 수행한다. 운영 배포를 직접 하지 않는다.

## 검사 스크립트의 기존 불일치

기존 e2e의 첫 화면 문구·데모 연결 링크는 이미 운영 main과 달랐다. 실제 링크(사전등록/현장 요청/내 요청/안내데스크)를 찾도록 검사 계약을 갱신했다. 예매 연결 → 이미 구현된 예약 조회 → 수동 항공편 선택 경로를 브라우저에서 검사하도록 업데이트하며, 제품의 API·데이터·화면 순서는 변경하지 않았다.


## 공통 구조 교체 중 발견/수정
- 모바일 사전등록 .flow-cta가 정적 배치여서 실제 포인터 클릭이 화면 밖으로 벗어나는 경우를 재현했다. 모바일에서 하단 sticky로 복원했다. 동의 문서를 읽는 단계의 cta-after는 기존 정적 동작을 보존한다.
- 어두운 항공편 판 .board-label이 보조 텍스트의 밝은 화면 토큰을 사용해 실제 대비 검사에서 실패했다. on-dark-muted로 수정했다.
- 현장 안내 첫 화면의 직원 도움 위치가 진행 화면과 달랐고, 지속 소리 안내 시작점도 빠져 있었다. 기존 StaffCall/ListenStart 부품을 이용해 위치 계약과 기존 설정 기능을 복원했다. API/데이터/화면 순서는 유지했다.
- 기존 개인 패스는 모의 체크인으로 QR을 새로 만들던 검사와 달리 현재 main에서 기존 탑승권 이미지 연결을 사용한다. 이미지 판독→연결→새로고침 유지와 별도 QR 미발급을 검사하도록 갱신했다.

## 테스트 범위 보정 기록
- main에서 이미 퇴역한 스티커 발급 UI 기대값은 삭제하고 현재의 기존 탑승권 이미지 연결·새로고침 후 유지·별도 지원 QR 미발급으로 대체했다. 옛 등록/호출 API 호환성은 별도로 보존 검사한다.
- 입구 로봇의 카메라는 현재 main에서 탑승권 불러오기 펼침을 열어야 시작된다. 시험도 실제 사용자처럼 펼친 뒤 판독을 기다린다.
- 이동지원 접수 성공 장면은 실행 시각(야간 18시 이후 등)에 의존하지 않도록 격리된 localhost에서만 거점 운영시간을 0~24시로 설정하고 장면 종료 후 원복한다. 실제 배포의 운영시간이나 API는 변경하지 않는다.
- T1 안내데스크 접수는 탑승동 직원의 권한과 다르므로 해당 장면은 안내데스크 세션으로 같은 요청을 배정한다. 다른 구역의 권한 거부 검사는 유지한다.
- 직원 호출 머리의 보조 문구도 어두운 배경 전용 토큰으로 수정했다(axe 5개 화면 동일 결함).

## 기능 흐름 개선 제안 — 이번 디자인 범위에서 미변경
- 시설 신고·일반 문의·이동지원의 질문 길이와 만남 여부는 서비스별로 별도 사용자 검증이 필요하다. 이번 작업은 기존 분기와 입력 항목을 보존한다.
- 외부 기관·실물 장비의 실제 연동 여부와 화면 디자인의 완성도는 별도 검증 사항이다. 기존 시연·미연동 표시는 지우지 않는다.

- 마지막 집계의 checkins는 기존 탑승권 연결 횟수가 아니라 명시적인 모의 체크인 API 호출 횟수다. 현재 시나리오의 2회 호출과 정확히 일치하는지 검사한다. 탑승권 이미지 연결은 API 상태를 별도로 검증한다. 제품의 집계 정의는 이번 작업에서 바꾸지 않았다.

## 2단계 적용
- 여객 화면 소유 규칙을 passenger.css로 분리. 넓은 노랑 판은 작은 강조선과 차분한 바탕으로 변경.
- 휴대전화 단일 열 / PC 등록 단계·입력·요약 영역. 첫 화면의 길 찾기와 서비스 목록을 서로 다른 작업 영역으로 구분.
- 예약·만남·체크포인트의 CSS module 및 스탬프의 글자 크기/굵기/간격/모서리를 공통 기준으로 정규화.
- 개인 안내의 고유 일련 번호는 기존 API가 제공하고 음성으로는 읽지만 화면에는 보이지 않던 값을 표시. 데이터나 조회 흐름은 미변경.
- 오류/없는 경로의 제목을 h1으로 수정(문구·이동 동작 동일).
- 모바일 시각 검사에서 발견한 CSS 순서 오류를 수정: 추출된 기본 규칙 뒤에 반응형 변형 배치.

- 모바일 등록의 고정 CTA가 선택지 일부를 가리는 axe target-size 오류를 발견했다. 입력 영역만 스크롤하고 CTA는 별도 영역에 배치한다. 전환 시 내부 스크롤을 맨 위로 초기화하며, 동의 화면은 본문과 CTA를 함께 스크롤한다.
