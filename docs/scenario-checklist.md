# 시나리오 점검표

실제 휴대전화와 모의 데이터로 끝까지 눌러 보는 점검이다. 명세 9장의 일곱 가지를 단계로 풀었다.
시작 전에 서버를 끄고 `npm run seed -- --mock-flights` 를 실행한 뒤 다시 켠다.

2026-10-05 로컬 브라우저 점검 결과를 오른쪽에 적었다. "확인"은 화면을 직접 눌러 본 것, "경로 호출"은 화면이 부르는 서버 경로를 직접 불러 응답을 본 것이다. 카메라 스캔은 한 번도 해 보지 못했다. 점검에 쓴 브라우저가 카메라를 막고 있어 패스 번호 입력으로 대신했다.

## 1. 등록부터 응대 완료까지

| 단계 | 기대 | 10-05 |
|---|---|---|
| `/register` 에서 동의 → 구분 → 도움 → 이름·편명 `MK101` | 접수 번호 네 자리 | 확인 |
| 없는 편명 `ZZ999` 로 찾기 | "편명을 다시 확인해 주세요…" | 확인 |
| 안내데스크(`100100`) → 패스 연결 → 접수 번호 → 패스 스캔 | "연결했습니다. 패스 번호 ####" | 확인 (번호 입력) |
| 같은 접수 번호를 다시 조회 | 찾을 수 없음 | 확인 |
| 현장 직원(`201132`) 목록 | 여객이 탑승구 101로, 마감 임박이면 붉게 | 확인 |
| 패스 스캔 → 여객 카드 | 소통 방식이 맨 위, 탑승구와 남은 시간(추정) | 확인 (번호 입력) |
| 응대 시작 → 응대 완료 | "응대를 기록했습니다." | 확인 |

## 2. 종이 체크리스트와 대신 입력

| 단계 | 기대 | 10-05 |
|---|---|---|
| 안내데스크 → 새로 등록 → 방법 선택 | 여객 등록과 같은 질문, 같은 순서 | 화면은 눌러 보지 않음 (여객 등록과 같은 부품을 쓴다) |
| 등록 후 바로 패스 스캔 | 접수 번호 없이 연결 | 경로 호출 |
| 공동운항 편명 `MC830` 으로 등록 | 카드에 탑승구 104, "운항 편명 MK300" | 확인 (카드 화면) |

## 3. 직원이 아닌 휴대전화로 QR 스캔

## 실제 휴대전화에서 다시 볼 것

- 카메라로 패스 QR 스캔 (Android Chrome, iOS Safari 각각)
- 휴대전화 기본 카메라로 찍어 `/p/{token}` 으로 들어오는 경로
- 면세구역·탑승동의 통신 상태에서 목록이 30초마다 갱신되는지
- 통신을 끊었을 때 "연결할 수 없습니다. 구두로 확인해 주세요"가 뜨고 목록이 지워지는지
- 여객 카드를 열어 두고 2분 뒤 목록으로 돌아가는지
