# 통합 업무 목록의 전체 검색·필터·우선순위

기존에는 페이지에 내려온 기록만 화면에서 필터링했다. 이제 전체 조회 대상에 같은 검색·필터를 적용한 뒤 건수와 페이지를 계산한다.

- 요청 번호, 관리된 픽업 지점 이름·코드와 변경 희망 지점을 검색한다. 건강 메모·지원 사유 같은 자유 텍스트를 검색하지 않는다.
- 서비스, 접수 경로, 새/이전 기록 종류, 담당 구역, 미배정·내 구역·위치 변경·확인 지연을 교차 필터링한다.
- 현재 목록과 최근 90일 이력 모두 같은 필터를 적용한다. 상세 위치가 삭제된 기록은 위치 검색으로 드러나지 않고, 남아 있는 요청 번호로만 메타데이터를 조회할 수 있다.
- 우선 정렬은 위치 변경 확인, 기존 지연 기준(미배정 10분/진행 중 갱신 30분), 나머지 미배정, 진행 중, 종료 순이다. 같은 분류에서는 오래된 접수부터 표시한다. 최신/오래된 순도 선택할 수 있다.
- 페이지당 25·50·100·200건을 선택한다. 새 화면은 50건 기본이며 기존 API 요청의 200건 기본은 유지한다.
- 필터 변경 시 첫 페이지로 돌아가고, 전체 일일 현황과 현재 검색 결과 건수·현재 페이지 건수를 구분한다.
- 새 필터 조회가 시작되면 이전 조회를 중단하고, 지연된 응답이나 과거 버튼 작업의 새로고침이 현재 검색 결과를 덮어쓰지 못하도록 한다.
- 검색·필터가 바뀐 것을 새 접수로 오인해 화면 소리 알림을 울리지 않는다. 화면 소리 알림은 현재 목록에 나타나는 새 접수를 대상으로 한다.

## 검증

230개 중 첫 200건 밖의 위치 검색, 같은 조건의 건수/페이지, 우선순위·FIFO·최신순, 담당 구역/경로/서비스 교차 조건, 세 원본 조회, 개인정보 삭제 후 검색, SQL 구문·와일드카드의 문자 처리와 잘못된 필터 거절을 검사한다.

브라우저에서는 검색·빈 결과·초기화·빠른 필터 전환 중 지연 응답·다음 페이지·페이지 초기화·모바일·접근성을 확인한다. 우선순위는 시범 목록의 표시 규칙이며 실제 긴급도 판단이나 장비 자동 배차가 아니다.
