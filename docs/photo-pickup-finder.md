# 현재 위치 찾기: 검색·사진 단서·직접 확인

긴 위치 목록을 기본 화면에서 접고, 게이트 번호·주변 안내판·안내데스크 이름 검색을 먼저 제공한다. 일반 현장 접수·사전등록 연결 접수·직원 대리 접수와 개인 요청의 위치 변경에 같은 선택기를 사용한다. 설치된 공용 키오스크는 고정 위치를 유지한다.

## 사진 처리

- 사용자가 선택한 사진은 브라우저에서 크기를 줄이고 영어·한국어 글자를 읽는다. Tesseract.js와 인식 모델은 처음 사용할 때 내려받는다.
- 사진·OCR 원문·EXIF 위치 정보는 요청 API로 전송하지 않는다. 이미지 미리보기는 임시 객체 URL이며 새 사진·수동 입력·화면 이동 시 해제한다. 서버에는 직접 확인한 기존 위치 ID만 보낸다.
- 사진을 읽었다고 위치를 자동 확정하지 않는다. ‘여기가 맞아요’를 눌러야 선택된다. 접수 최종 확인과 배정 후 위치 변경의 직원 확인 절차는 유지한다.
- 여러 번호·방향 안내 또는 구역과 맞지 않는 번호는 확인이 필요하다고 표시한다. 가격·전화번호·날짜의 숫자를 그대로 위치로 쓰지 않는다.
- 인식 취소·다른 사진·수동 검색 후 늦게 도착한 OCR 결과는 버린다. 읽기 실패·시간 초과·지원하지 않는 형식이면 검색·직접 선택으로 진행할 수 있다.
- 사진 형식은 브라우저에서 해독할 수 있는 JPEG·PNG·WebP·AVIF·HEIC/HEIF다. 일부 기기에서 해독할 수 없는 형식은 JPG/PNG나 수동 검색을 안내한다. 20MB 이하로 제한한다.

## 위치 데이터의 범위

기존 시연 지도와 직원 구역 기준으로 T1 1–50, 탑승동 101–132, T2 208–291의 166개 게이트 번호를 지원한다. 기존 대표 지점의 ID는 유지하며 새 게이트 지점만 추가한다. 예를 들어 127번 사진을 125번 만남 지점으로 임의 변환하지 않는다. 이 구역·거리 자료는 모의 지도이며 실제 기관의 실내 지도·운영 지점 확정이 아니다.

실제 매장별 위치 DB는 연결하지 않았다. 등록된 안내데스크·도착장·셔틀트레인 명칭과 게이트 단서는 찾을 수 있지만, 매장 상호나 로고만으로 위치를 추정하지 않는다. 매장 사진은 주변 게이트·안내판을 함께 찍도록 안내한다. 미등록 매장은 검색이나 안내데스크의 현장 확인으로 이어간다.

새 DB 열·사진 저장소·외부 이미지 분석 API·유료 모델은 필요 없다. 직원 목록 검색과 서버 위치 검증은 새 게이트 ID를 지원하며 원래 배정·인계·장비·개인정보 정책을 유지한다.

## 검증

`tests/place-search.test.ts`: 한국어·영어·OCR 오독 문자, 번호·구역 불일치, 방향 표지, 미등록 매장, 숫자 오인, 지도·직원 구역 일치와 파일 검증.

`scripts/pickup-finder-e2e.ts`: 실제 OCR로 게이트 사진 읽기 → 사용자 확인 → 기존 요청 API 저장, 사진 미전송, 위치 변경, 영어·모바일·접근성, 취소 후 오래된 결과 방지, 읽기 실패 후 수동 복구.

`scripts/demo-journey-e2e.ts`의 대표 시연도 게이트 검색·후보 확인을 통해 현재 위치를 선택한다.
