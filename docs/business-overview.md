# 업무별 통합 운영 현황

안내데스크의 `/staff/overview`에서 기존 호출·이동지원과 신규 통합 요청을 공통 업무 뷰로 집계한다. 여객 식별값·요청 번호·자유 입력 내용은 현황 API에 포함하지 않는다.

## 집계 기준

- 현재 진행·미배정·지연은 보관 기간 내 열린 요청 전체다. 전날 접수도 포함한다.
- 오늘 접수는 한국시간 00시부터 기준 시각까지 생성한 요청이다. 사전등록 정보 연결은 그 부분집합이다.
- 오늘 완료·기타 종료는 종료 시각이 오늘인 요청이다. 전날 접수를 포함하므로 오늘 접수와 같은 모집단이 아니다.
- 배정·완료 시간의 중앙값은 각각 오늘 배정·완료된 요청 기준이다. 음수·미래 시각은 제외하고, 자료가 없으면 0으로 꾸미지 않는다.
- 완료 결과는 상담·창구 안내·인계 확인·현장 조치 확인·미기록/보관 종료로 분리한다. 시간 초과나 창구 안내를 실제 문제 해결로 집계하지 않는다.
- 담당 업무가 없거나 현재 목록에 없는 기록은 미분류·이전 요청으로 집계한다. 개인정보 정리로 분류가 지워진 기록도 여기에 포함한다. 과거 업무·결과를 추정하지 않는다.
- 12개 업무와 미분류 행은 0건이어도 표시한다. 분야 선택은 표·카드만 좁히며 상단 전체 집계는 바꾸지 않는다.
- 진행 수치의 막대는 업무 사이의 상대 건수다. 부서의 처리 용량·직원 수·장비 가용률을 뜻하지 않는다.

단일 SQL 집계에서 전체와 업무별 수치를 함께 계산한다. 개인정보 보관 정리는 기존 정책을 따른다. 이번 변경에 새 DB 열·테이블·시드는 필요 없다.

## 처리 화면과 연결

진행·미배정·지연 숫자는 해당 업무와 상태로 필터링된 `/staff/requests`로 연결한다. 진행 전용 범위(`scope=active`)와 미분류 업무 범위(`business=unclassified`)를 추가했다. 일반 요청 목록의 기존 필터도 유지한다.

## 갱신과 권한

최초 화면은 서버에서 집계하고, 30초마다·창으로 돌아올 때·새로고침 버튼을 누를 때 다시 조회한다. 실패하면 기준 시각과 마지막 받은 현황을 남기고 오류를 표시한다. 다시 연결되면 갱신한다. 화면과 API 모두 안내데스크 권한을 요구하며 일반 직원·키오스크·만료 세션은 허용하지 않는다.

기존 사전등록·이용 지표는 `/staff/desk/stats`에 유지하고 현황에서 연결한다. 실제 부서 시스템·직원 근무표·장비 API와의 연동은 별도 범위다.

## 검증

`tests/business-overview.test.ts`는 한국시간 자정, 전날 진행, 완료 결과 구분, 지연 기준, 원본 기록 중복 방지, 권한, 개인정보 제외, 보관 종료와 목록 필터 일치를 검사한다.

`scripts/business-overview-e2e.ts`는 로컬 전용 브라우저에서 PC 표·모바일 카드, 업무 필터·처리 화면 이동, 결과 구분, 접근성·오류 복구를 검사한다.
