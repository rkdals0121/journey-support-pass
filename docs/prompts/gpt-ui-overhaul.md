# GPT(Codex)에게 줄 프롬프트: 화면 통일·한 화면 맞춤 작업

아래 「---」 사이를 그대로 복사해서 GPT 에게 준다. 화면 묶음을 바꿔 가며 같은 프롬프트를 여러 번 쓸 수 있게 맨 아래 「이번 작업 범위」만 고친다.

---

너는 이 저장소(Journey Support Pass, Next.js)의 화면을 고치는 프런트엔드 작업자다. 아래 순서와 규칙을 **정확히** 지켜라. 규칙을 어길 이유가 생기면 고치기 전에 멈추고 그 이유를 나에게 먼저 물어라.

## 0. 먼저 읽을 것 (읽기 전에 코드를 고치지 마라)
1. `AGENTS.md` — 공통 규칙
2. `docs/ui-guide.md` — 화면 틀·끝선·한 화면 맞춤·확인 방법. **이 문서가 이번 작업의 기준이다.**
3. 기준 화면 코드: `src/app/page.tsx`, `src/app/components/TaskHome.tsx`, `src/app/styles/passenger-layout.css`(`.ph-hero`, `.ph-list .task-action`), `src/app/styles/site-bar.css`
읽은 뒤, 이번 범위의 화면이 기준 화면과 **어디가 다른지** 표로 정리해서 먼저 보여 줘라(화면, 다른 점, 고칠 방법). 내가 확인하기 전에는 코드를 고치지 마라.

## 1. 목표
- 어떤 화면이든 **스크롤을 최소로**. 키오스크(1920×1080, 1024×768, 1080×1920)는 **스크롤 0**, 노트북(1280×633, 1333×750, 1366×657, 1920×937)의 첫 화면·짧은 화면도 스크롤 0.
- 모든 화면이 웹 첫 화면(`/`)과 **같은 틀**: 둥근 위쪽 바, 노란 그라데이션 소개 박스, 흰 카드 + 아이콘 칩, 딥그린 주요 버튼, 노랑 강조는 한 곳.
- **모든 덩어리의 좌우 끝 = 위쪽 바의 좌우 끝.** 나란한 카드는 높이가 같다.
- **글은 최소로**: 제목 한 줄 + 짧은 한 줄. 여러 줄 설명 문단 금지.
- 보기 좋아야 한다. 휑하거나 꽉 막히지 않게, 간격은 한 화면에서 한 값.

## 2. 절대 하지 말 것 (지난 작업에서 실제로 문제가 됐던 것들)
- `src/app/layout.tsx` 끝에 새 CSS 파일 추가, 같은 선택자를 두 파일에 정의, `!important`, 선택자를 길게 늘여 이기기.
- 색 코드(#…) 직접 쓰기, 고정 px 너비·높이(선 1px·기존 토큰 예외).
- `overflow: hidden/clip`으로 넘친 내용 숨기기. 기능 버튼을 빼서 높이 맞추기.
- 「도움 요청하기」(`.call-btn`), 「소리로 안내 듣기」(`.listen-start`), 글자 크기 설정을 없애거나 자리를 바꾸기.
- e2e 가 쓰는 클래스·문구를 바꾸고 `scripts/e2e.ts`를 안 고치기.
- `main`에 직접 push, 직접 병합, 배포. 여러 화면 묶음을 한 PR 에 섞기.
- **확인하지 않은 것을 「됐다」고 보고하기.** 재지 않았으면 「재지 않음」이라고 써라.
- 영어로 보고하기. 보고는 **한국어**로.

## 3. 작업 순서 (화면 묶음 하나마다)
1. `git pull`로 최신 `main`을 받고 새 갈래를 만든다: `design/<묶음이름>`.
2. 개발 서버를 띄우고, 고칠 화면을 **바꾸기 전에** 아래 크기로 열어 실측한다(`docs/ui-guide.md` 6절의 콘솔 코드). 결과를 표로 남긴다.
3. 고친다. 기준 화면의 부품(클래스)을 재사용하고, 새 규칙은 그 화면을 맡은 원래 CSS 파일에 쓴다(`AGENTS.md` 4절의 파일 목록).
4. 바꾼 뒤 같은 크기로 다시 실측한다. 기준을 못 맞추면 「넘치면 줄이는 순서」(여백 → 그림 → 보조 글 → 글자 한 단계)대로 다시 고친다.
5. 점검을 돌린다.
   ```bash
   npx tsc --noEmit -p .
   npx eslint src
   npx vitest run
   npx tsx scripts/layout-check.ts
   npx tsx scripts/e2e.ts   # 화면 흐름·문구를 바꿨을 때. 도는 동안 파일을 고치지 마라
   ```
6. 커밋하고 push 한 뒤 PR 을 연다. 병합은 하지 마라.
7. 아래 형식으로 보고하고 **멈춰라**. 다음 묶음은 내가 시키면 한다.

## 4. 보고 형식 (한국어)
```
## 바꾼 화면
- (주소) : 무엇을 어떻게

## 크기별 실측 (바꾸기 전 → 뒤)
| 화면 | 크기 | 세로(doc/vh) | 옆 넘침 | 바와 끝선 |
|---|---|---|---|---|

## 점검
- tsc / eslint / vitest : 결과
- layout-check : 문제 N개 (새로 생긴 것 / 원래 있던 것)
- e2e : 통과 N / 전체 M, 실패가 있으면 원인

## 화면 그림
- 바꾸기 전 / 뒤 (휴대전화 390, 노트북 1333×750, 키오스크면 1920×1080·1024×768·1080×1920)

## 확인 못 한 것 / 남은 문제
- (솔직하게)

## PR
- 링크
```
