# 접수 경로 공통 중복 방지

새 통합 요청, 이전 직원 호출, 이전 이동지원이 같은 사전등록·서비스에 대해 공통 활성 접수 잠금을 사용한다. 기존 화면을 열어 둔 상태에서 새 경로와 동시에 접수해도 DB의 공통 기본키가 두 번째 접수를 차단한다.

## 동작과 보존
- 익명 요청은 접수 확인값을 이용한 기존 중복 방지를 유지한다. 사전등록을 연결하지 않은 서로 다른 사람을 임의로 같은 사람으로 취급하지 않는다.
- 사전등록·서비스별로 활성 원본의 ID를 기록한다. 신규 경로만의 기존 ‘등록당 활성 요청 한 건’ 제한도 유지한다.
- 원본 삽입·등록 연결 변경·종료·삭제와 잠금 변경은 같은 트랜잭션에서 수행한다. 요청 거절 시 사용 한도나 알림 기록도 남지 않는다.
- 기존 호출에 다음 여객의 패스를 붙일 때는 이전/다음 잠금 키를 같은 순서로 잠근다. 배정된 호출의 여객을 바꾸지 않는 기존 규칙은 유지한다.
- 취소·지원 종료·시간 초과·개인정보 삭제 시 활성 잠금을 해제한다.
- 과거에 이미 생긴 중복은 원본을 지우거나 완료 처리하지 않는다. 잠금 소유자를 비워 추가 접수를 차단하고, 통합 목록에 과거 중복 확인 대상으로 표시한다. 관련 활성 기록이 모두 종료되면 잠금을 해제한다.
- 이전 API도 중복 접수에 일반 서버 오류 대신 409와 설명을 반환한다. 새 요청의 영어 화면에도 기존 요청 확인 안내를 표시한다.

## 스키마 적용
- 스키마 묶음은 동일한 DB 연결의 트랜잭션에서 적용한다. 실패 시 롤백하고 연결을 정리한다.
- 세 원본의 쓰기를 잠근 상태에서 공통 잠금의 초기 값을 채우고 트리거를 설치해 전환 중 접수가 빠지는 틈을 막는다.
- 기존 구역 코드·항공편·여객의 요청 상태를 초기화하지 않는다.

## 검증
- 새/이전 안내·이동지원 동시 접수, 이전 API의 직접 삽입, 확인 후 삽입 직전 경쟁, 익명 호출에 패스 연결, 취소 후 재접수, 여러 서비스, 개인정보 삭제, 원본 삭제, 기존 중복의 이전·보존·해제, 다른 DB 오류의 전파를 검사한다.
- 별도 브라우저 경로의 동시 요청과 영어 오류 복구 화면을 확인한다.

## 한계
- 연결된 사전등록과 같은 서비스가 기준이다. 연결 정보가 없는 두 익명 기기의 사람 동일성은 판단하지 않는다.
- 기존 중복을 임의로 하나로 합치지 않는다. 실제 진행 여부와 종료할 기록은 담당자가 확인해야 한다.
- 실제 장비 배차나 서비스 예약 확정과는 별개다.
