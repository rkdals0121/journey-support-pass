# 접수 알림 대기열과 확인 기록

접수와 동시에 알림 작업을 DB에 저장하고, 푸시 발송을 접수 응답 뒤에 실행한다. 푸시 실패가 접수 성공 여부를 바꾸지 않으며, 서버 종료 후에도 대기 기록을 다시 처리할 수 있다.

## 구현
- 새 통합 요청 삽입과 알림 사건·당시 활성 구독 기기 목록 저장을 같은 DB 트랜잭션에서 수행한다. 재접수 확인값 재시도는 새 알림 사건을 만들지 않는다.
- 대기 작업을 행 잠금과 임대 토큰으로 가져와 여러 실행기의 중복 처리를 방지한다. 중단된 실행은 30초 임대가 끝난 뒤 복구한다.
- 네트워크 오류·일시적 서버 오류·429는 최초 시도를 포함해 최대 4회 시도한다. 재시도 간격은 15·30·60초다. 다음 실행 시각이 지난 작업만 처리한다.
- 404·410 구독은 정리한다. 일반적인 영구 4xx 오류는 반복하지 않는다.
- 접수 10분이 지났거나 직원이 확인·배정했거나 요청이 종료되면 남은 발송을 중단한다. 이미 네트워크로 전송 중인 푸시는 도착할 수 있다.
- 푸시 서버 접수, 서비스워커가 알림 표시 뒤 보낸 수신 확인, 직원의 명시적 ‘접수 확인’을 따로 기록한다. 직원 확인은 최초 확인 구역과 시각만 저장하며 배정이나 요청 버전을 변경하지 않는다.
- 수신 확인값은 서버 서명으로 검증하고 해당 발송의 수신 표시만 허용한다. 여객 접수 확인값이나 내용 조회 권한으로 사용할 수 없다.
- 서비스워커는 여객의 위치·불편 사항·말씀을 표시하지 않고 일반 문구만 표시한다.
- 통합 요청의 카드와 안내데스크 알림 운영 화면에서 상태를 확인한다. 기기별 전달 기록은 24시간 보관하고, 익명 구역의 최초 확인 기록은 요청 보관 기간을 따른다.

## 실행 경로와 남은 설정
- 최초 발송: 접수 API 응답 뒤 Next.js after()에서 실행.
- 재시도: 인증된 직원의 통합 요청 조회, 안내데스크의 ‘재시도 대기 처리’, 보호된 GET /api/cron/request-alerts 실행.
- 외부 예약 실행은 Authorization: Bearer CRON_SECRET으로 위 경로를 호출해야 한다. 비밀값은 파일·화면·알림에 노출하지 않는다.
- 2026-10-26 프로덕션에 VAPID 공개 키·비밀 키·HTTPS subject를 등록하고 재배포했다. 비밀 키는 저장소에 포함하지 않는다. 실제 휴대전화 수신 검증은 별도 기기 확인이 필요하다.
- 현재 Vercel Hobby 요금제를 유지한다. 사용자가 선택한 GitHub Actions `request-alerts.yml`이 UTC 매시 2·7·12…57분에 보호된 재시도 API를 호출한다. 저장소 Secret `REQUEST_ALERTS_CRON_SECRET`을 사용하며 checkout·외부 action 없이 고정 HTTPS 주소만 호출한다.
- 수동 실행은 기본 브랜치 main에서만 허용한다. 동시 실행은 직렬화하며, 실패는 Actions 실행 결과에 남는다. Secret 변경 시 GitHub와 Vercel 양쪽을 함께 갱신한다.
- GitHub 예약은 정확한 5분 간격을 보장하지 않으며 지연·누락될 수 있다. 공개 저장소의 60일 비활동 시 예약 중단도 확인해야 한다. 접수 10분 만료를 유지하므로 최대 4회 시도가 항상 실행되는 것은 아니다. 실제 운영에서 분 단위 재시도 보장이 필요하면 별도 실행 기반을 마련해야 한다.
- 정확히 한 번의 외부 전달을 보장하지 않는다. 네트워크 응답이 유실되면 같은 태그의 알림이 재전송될 수 있다. 수신 확인 콜백이 실패하면 수신 여부는 미확인으로 남는다.
- 이번 버전 이전 요청 및 이전 호출·이동지원에 과거 알림 이력을 만들어 넣지 않는다. 기존 현장 진입 경로는 새 통합 요청을 사용한다.

## 검증 범위
- 접수와 알림 원자성, 동시 실행, 임대 복구, 시도 횟수·간격, 구독 폐기·로그아웃·구역 전환, 직원 확인·배정·기간 종료 후 발송 중단을 검사한다.
- 서버 접수·기기 수신·직원 확인을 구분하고 수신 확인값 위조·만료·중복을 검사한다.
- 실제 브라우저에서 직원 확인, 새로고침 보존, 요청 상태 불변, 취소 유지, 운영 설정 없음 표시와 모바일 화면을 확인한다.
